
## 5. Сценарии животноводства (СВН + КРС)

Начиная с версии комплекта 006 в покрытие включён животноводческий контур
АПК: **свиноводство (СВН)** и **молочный КРС**. Порядок запуска — тот же, что в
§3 (скан → генерация фич → прогон): никаких отдельных шагов не требуется;
шаблоны срабатывают автоматически по найденным в базе документам животноводства.

### 5.2. Специфика животноводческих сценариев

1. **Запись перед проведением**. Формы документов КРС не проводят документ,
   который не записан. Сгенерированные фичи используют порядок: «Записать» →
   дождаться присвоения номера → «Провести». Это встроено в шаблоны, менять
   вручную не нужно.
2. **Период АРМ**. АРМ-шаблоны вводят период начала/конца месяца рабочей даты
   сеанса (плейсхолдеры `{{period.start}}` / `{{period.end}}` подставляет
   препроцессор). Жёстких дат в шаблонах нет — при смене рабочей даты ничего
   править не нужно.
3. **Негативный сценарий животноводства**. Пользователь без прав (см. §2.6)
   пытается открыть и записать групповой опорос. В платформе 8.5 отказ может
   выглядеть как окно «Не удалось перейти по навигационной ссылке» без текста
   о правах — это ожидаемое поведение, раннер распознаёт его как отказ прав
   (`neg-passed`).

### 5.3. Известные особенности (не ошибки комплекта)

| Особенность | Пояснение |
|---|---|
| `19-krs-transfer` по документу НВ00-000002 заканчивается записью без проведения | Конкретный демо-документ базы непроводим (ошибка данных, воспроизводится и вручную); сценарий для него завершается успешно после записи |
| Сводный документ по реализации молока не тестируется | Формируется автоматически, проведение отключено в метаданных (Posting=Deny); молочный контур покрыт первичными документами 16/22/23 |
| Часть КРС-сценариев выполняется по 2 представителям одного типа | Если в базе найдено несколько документов одного типа с разными авторами — генерируется по фиче на автора (проверка прав разных пользователей) |

### 5.4. Таймаут батча

Животноводческие батчи длиннее растениеводческих (в одном батче может
собраться 15+ сценариев одного автора). Рекомендуемое значение
`timeoutMinutesPerBatch` — **25 минут** (значение по умолчанию в коде — 10;
на стенде проекта применяется 25). Симптом заниженного таймаута: статус батча
`timeout` при зелёных остальных батчах, в отчёте — `MISSING` по сценариям
автора этого батча.
