# План: пользовательская документация релиза «Раннер + сценарии»

> Задача: оператор на сторонней базе заказчика (1С:ERP+АПК 2.5) без
> python/COM/LLM должен: подготовить окружение → настроить раннер →
> запустить прогон → прочитать отчёт. Документация — часть релиза
> комплекта `dist/`.
> Статус: план утверждён, исполнение — ночная сессия
> (`docs/night-prompt-2026-11-03-user-docs.md`).

## 1. Что создаём (артефакты)

| Артефакт | Объём | Назначение |
|---|---|---|
| `dist/БЫСТРЫЙ-СТАРТ.md` | 1–2 экрана | краткая версия: чеклист требований → 4 шага → как читать вердикт → что делать при красном |
| `dist/РУКОВОДСТВО-ОПЕРАТОРА.md` | 8–12 экранов | подробная версия (структура ниже) |
| `docs/screenshots/*.png` | ≥8 файлов | мастер-копии скриншотов (для правок документации) |
| `dist/screenshots/*.png` | те же | скриншоты в составе комплекта (ссылки из руководства) |
| правки `README.md`, `dist/ИНСТРУКЦИЯ.md` | точечные | ссылки на новую документацию |

Оба документа — только про чистый 1С-комплект (без python).
Терминология — по словарю `docs/how-tester-works.md` (батч → группа
проверок, гейт → полный прогон, baseline → эталон и т. д.).

## 2. Структура подробного руководства

1. **О комплекте** — что делает, принцип работы (сжато + ссылка на
   схемы `docs/how-tester-works.md`), состав `dist/`, совместимость
   (1С:Предприятие 8.5, 1С:ERP+АПК 2.5, Windows; VanessaExt; расширение
   VAExtension).
2. **Как подготовить** — требования к машине и базе; состав комплекта
   и куда раскладывать; учётная запись администратора; проверка окружения
   перед первым запуском (чеклист); ограничения (Linux не поддерживается,
   нужен свободный сеанс).
3. **Как настроить раннер** — параметры настроек прогона (по фактическим
   ключам форм): путь к 1cv8 и Vanessa, строка базы, пользователь и
   пароль администратора, каталог шаблонов и карта покрытия, базовый порт
   TestClient, тип клиента (тонкий/веб), таймаут группы, подмена паролей
   (`alwaysSubstitutePwd`), контур-фильтр (растениеводство / СВН / КРС /
   АРМ); где хранится файл настроек, как выглядит форма; безопасность
   паролей (хэш сохраняется/восстанавливается).
4. **Как запускать** — пошаговый сценарий со скриншотами: открыть
   препроцессор от администратора → скан (фильтры, результат, пропуски
   с причинами) → фикстуры и генерация сценариев → запуск раннера →
   группы проверок (ожидание, окна) → вердикт. Ожидаемое время этапов.
5. **Как смотреть отчёт** — итоговая форма отчёта (элементы, статусы
   «прошла/провалилась/отказ», вердикт ГОДЕН/НЕ ГОДЕН), сводка по
   группам, сравнение с эталоном (прошло/провалилось/пропущено/новое),
   отчёт Allure, как читать строку провала; типовые действия при
   провале.
6. **Приложение А** — словарь терминов (перенести из
   `docs/how-tester-works.md`).
7. **Приложение Б** — частые проблемы и решения (перенести/сократить
   из `dist/ИНСТРУКЦИЯ.md` §4 и `docs/runbook.md` §4).

Краткая версия (`БЫСТРЫЙ-СТАРТ.md`) — выжимка разделов 2–5 в формате
«одна страница»: чеклист, 4 шага, мини-картинка вердикта, ссылка на
подробное руководство.

## 3. Обязательные скриншоты (≥8)

| № | Что показывает | Источник |
|---|---|---|
| 1 | Запуск обработки препроцессора из 1С (от администратора) | сеанс 1С |
| 2 | Форма препроцессора: фильтры сканирования (контур, период, виды документов) | сеанс 1С |
| 3 | Результат сканирования: план, фикстуры, пропуски с причинами | сеанс 1С |
| 4 | Форма раннера: параметры прогона | сеанс 1С |
| 5 | Процесс прогона: окно группы проверок (Vanessa/TestClient) | сеанс 1С |
| 6 | Итоговая форма отчёта: вердикт и сводка | сеанс 1С |
| 7 | Детали строки отчёта: сценарий × пользователь × статус | сеанс 1С |
| 8 | Отчёт Allure в браузере (при наличии) | браузер |

Правила съёмки: фиксированный размер окна, закрыты посторонние окна,
читаемые шрифты, PNG; имена — `screenshot-01-…png` … `screenshot-08-…png`.
Если съёмка в текущей сессии невозможна (headless) — использовать
имеющиеся артефакты (видео/скриншоты из `docs/evidence/`, allure-вложения,
архивы tmp) и пометить места «скриншот будет добавлен при интерактивной
сессии»; НЕ рисовать картинки и НЕ выдумывать интерфейс.

## 4. Источники фактов (без выдумок)

- XML-исходники форм: `src/АпкПодготовкаСценарныхТестов/`,
  `src/АпкРаннер/` — реальные названия кнопок, полей, колонок.
- Ключи настроек: `ObjectModule.bsl` (projectDir, templatesDir,
  coverageMapPath, v8cPath, vaEpfPath, infoBase, adminUser, adminPassword,
  timeoutMinutesPerBatch, portBase, clientType, webUrl,
  alwaysSubstitutePwd, maxTabularRows, runsBaseDir).
- `dist/ИНСТРУКЦИЯ.md` — среда, ограничения, частые проблемы.
- `docs/how-tester-works.md` — принципы и словарь терминов.
- `docs/runbook.md` §4 — диагностика (только переносимое, без python).

## 5. Этапы исполнения (ночная сессия)

| Шаг | Задача | Гейт |
|---|---|---|
| T0 | pre-flight: диск, сеансы, наличие dist/, доступен ли GUI | отчёт о среде |
| T1 | разведка форм: точные названия элементов для текста | список элементов |

| T3 | написание БЫСТРЫЙ-СТАРТ + РУКОВОДСТВО-ОПЕРАТОРА (вычитка ru-text) | оба файла |
| T4 | интеграция: скриншоты в тексте, ссылки README/ИНСТРУКЦИЯ/how-tester-works, копия скриншотов в dist/ | ссылки работают |
| T5 | финал: heartbeat, отчёт сессии, next-промт | отчёт |

## 6. Ограничения

- Никаких правок кода/BSL/сценариев — только документация. Всплывший
  баг раннера — зафиксировать в отчёте, НЕ чинить ночью.
- Без restore/dump/пересоздания базы; без изменения эталона
  `tests/baseline/`.
- Commit+push — только после подтверждения пользователя (утром).
- Скриншоты — только реальные (съёмка окон или имеющиеся артефакты).

## 7. Проверка качества

- Все ссылки и картинки открываются; пути относительные (работают и из
  `dist/`, и из репозитория).
- Термины совпадают со словарём `docs/how-tester-works.md`.
- Краткая версия читается за ~3 минуты и самодостаточна.
- Подробное руководство — без python-шагов на основном пути.
