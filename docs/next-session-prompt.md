  из шаблонов `tests/templates/` с подстановкой + fixtures.json артефакт;

## Доказанные механизмы (спайки PASS, не проверяй заново — бери готовое)

1. **Хэш пароля** (`docs/spike-password-hash.md`, `scripts/spike_password_hash.py`):
   `ПользовательИБ.СохраняемоеЗначениеПароля` (чтение+запись, админ) —
   сохранить → `Пароль = <тестовый>` → Записать → прогон → вернуть хэш →
   Записать. Старый пароль снова принимается, тестовый отвергается.
   Нюансы: `ДатаУстановкиПароля` не откатывается (вернуть через
   `ЗаписываемаяДатаУстановкиПароля`, если важно); восстановление —
   гарантированный finally-блок.
2. **Прогон VA под пользователем** (`docs/spike-user-run.md`,
   `scripts/spike_user_run.py`): полный цикл работает, ReturnStatus=0.
   VAParams: TestManager под админом, `КлиентыТестирования[0]` с
   `/N "<пользователь>" /P "<тестовый пароль>"`, порт свой на прогон.
3. **Вердикт прогона** — ТОЛЬКО ReturnStatus-файл
   (`ВыгружатьСтатусВыполненияСценариевВФайл` + путь): 0=ок, 1=ошибки
   сценариев, 2=проблемы подключения TestClient, 3=нет сценариев,
   4=не встала компонента. Строку в `/Out` не лови (может быть пуста).
   Код возврата процесса всегда 0 — не верь ему.
4. **Allure**: VAParams `ДелатьОтчетВФорматеАллюр=Истина`,
   `КаталогВыгрузкиAllureБазовый` (подкаталог на сборку — для мульти-прогонов
   пользователь×сценарий), `ИмяТекущейСборки`,
   `ДобавлятьКИмениСценарияУсловияВыгрузки`. Результат:
   `<база>/<сборка>/<uuid>-result.json` (status, steps[], labels) +
   `-container.json`. Своя сводка парсит result-json'ы.
5. **Смоук-фича** `tests/features/smoke-01-connect.feature` — эталон
   минимального сценария (Контекст: «Дано Я запускаю сценарий открытия
   TestClient или подключаю уже существующий»).

## Грабли (реально наступлены — обходи сразу)

- НЕ открывай `/Out`-файл в Python при передаче его же в `/Out` — конфликт
  совместного доступа (1cv8c сам пишет в файл; читай после завершения).
- `ПользовательИБ.Роли.Добавить()` принимает ОБЪЕКТ роли метаданных
  (`Метаданные.Роли.<Имя>`), не строку — иначе «Несоответствие типов».
- COM-мост (pywin32) НЕ пишет 1С-UUID в UUID-реквизиты справочника (молча
  нулевой). Препроцессинг работает 1С-кодом — не актуально; но в
  python-зондах UUID через COM не писать/не читать (стрингифицируй
  `XMLСтрока()`, только чтение).
- ERP при старте сеанса требует сопоставления ИБ-пользователя со
  Справочник.Пользователи; автосоздание — только при ролях
  `ПолныеПрава`+`АдминистраторСистемы` (обе). Реальные авторы документов
  уже сопоставлены — для них это не проблема.
- Кириллица в bash/CLI-аргументах НЕ надёжна (транспорт мнёт): только через
  python-скрипты-файлы (write-инструмент) или `\u`-эскейпы; сравнивай байты,
  не отображение. В python-аргументах bash не разворачивает `\u` —
  декодируй `codecs.decode(s,'unicode_escape')`.
- XML исходников 1С: root `{MDClasses}MetaDataObject`, реквизиты объектов —
  в `ChildObjects/Attribute` (не в `Properties`); namespace обязателен.
- Таймаут + kill дерева процессов обязательны на каждом VA-прогоне.
- В рабочей базе крутится designer-агент APKTechPlan (1cv8.exe DESIGNER
  /AgentMode) — НЕ трогай его процесс.

## Что положить в спеку 001 (подсказка структуры, не догма)

Функциональные блоки EPF `АпкСценПрепроцессор` (имя обсудим в спеке):
формы+серверный модуль; **Сканер** документов АПК за период/организацией
(фильтры в форме, D5; перечень — fixture-model.md); **Извлекатель фикстур**
(данные → fixtures.json, модель — docs/fixture-model.md, N строк ТЧ ≈ 3);
**Менеджер паролей** (хэш-механизм, finally-восстановление, учёт
пользователей без пароля, ЗОД-предупреждения офф на прогон);
**Генератор фич** (шаблоны → run-каталог); **Раннер VA** (VAParams per run,
TestManager под админом, TestClient под целевым пользователем, таймауты,
kill-tree, ReturnStatus); **Репортёр** (парсинг allure result-json +
fixtures.json → сводка сценарий×пользователь×статус). Приоритет
Web-клиента — вне 001 (Фаза 4). Нефункциональные: гейты bsl-ls+v8std,
compile-gate EPF, smoke-прогон, время прогона, переносимость на другую базу.
