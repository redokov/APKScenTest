## Ключевая домен-информация: полная цепочка АРМов растениеводства

**АРМ «По отражению выработки сотрудников» (АпкАРМПоОтражениюВыработкиСотрудников) —
ФИНАЛЬНЫЙ в серии.** Его Дерево корректно наполняется только когда вся цепочка
до него уже отражена. Порядок (все АРМ = обработки `АпкАРМПоОтражению*`):

1. АРМ по отражению **заправок топлива** (arm-fuel-receipt, после фикстур 04-fuel-sheet).
2. АРМ по отражению **расхода топлива** (arm-fuel-expense, после 01/02/04).
3. АРМ по отражению **выпуска урожая с поля** — если были фикстуры 05-weighing
   (взвешивания «поле», ВидВзвешивания).
4. АРМ по отражению **перемещений между складами** — если были такие документы.
5. АРМ по отражению **выпуска услуг** (АпкАРМПоОтражениюВыпускаУслуг) — **формирует и
   проводит ПБЗ** (Документ.ПроизводствоБезЗаказа), которые и «мешали» АРМ выработки.
6. АРМ по отражению **производства продукции растениеводства**.
7. АРМ для **видов работ, начисляемых процентом от других сотрудников** — если
   такие есть в фикстурах.
8. АРМ по отражению **выработки сотрудников** (АпкАРМПоОтражениюВыработкиСотрудников) — ПОСЛЕДНИЙ.

Какие АРМы актуальны для наших probe-фикстур (октябрь 2026): наряды run19/20
(АпкСводОплатыТруда), топливные листы (04), взвешивания (05) — точный состав
определяется по данным: субагент через COM проверяет регистры/данные АРМов
(`ПолучитьСостояниеОтражения` каждого АРМа, где есть) за октябрь 2026.
Имена обработок недостающих АРМов найти в `C:/MyProjects/APKModSrc/DataProcessors/`.

**Это снимает «блокер» прошлой сессии**: Дерево=0 у АРМ выработки — потому что
предшествующие АРМы (заправки/расход топлива и др.) НЕ отражены. Лечится не удалением
ПБЗ, а прогоном ПОЛНОЙ цепочки в правильном порядке. ПБЗ из прошлого прогона —
probe-артефакт, при необходимости пересоздаётся повторным прогоном probe-arm-vyusl
(образец проверки: `python tmp/s2/q_pbz.py` → «ПБЗ октябрь 2026: N»).

- Образцы: `tmp/s2/q_arm_state3.py` (диагноз Выпуск услуг), `tmp/t8/q_arm_vs_state.py`

- **Поля выборки читать ТОЛЬКО внутри цикла `while sel.Next()`** — доступ после
  цикла возвращает ПУСТЫЕ значения (дало ложный диагноз в прошлой сессии).
- Даты: `NewObject("Дата", ...)` НЕ работает → запросом `ВЫБРАТЬ ДАТАВРЕМЯ(...)`.
- Пустая ссылка: `= ЗНАЧЕНИЕ(Справочник.Имя.ПустаяСсылка)`; представления: `ПРЕДСТАВЛЕНИЕ(х)`.
- `ПолучитьСостояниеОтражения` АРМов вызывать из COM — ГЛАВНЫЙ инструмент диагностики
  (формы — нельзя). Параметры: Период=Структура{ДатаНачала,ДатаОкончания}, МассивОрганизаций,
  ВыводитьТолькоТребующееОтражения, ОтобразитьИсключенные (+Исполнитель у АРМа выработки).
  `ЗапуститьОтражение`/`СформироватьДокументыОтражения` из COM НЕ звать (многопоточность).
- `NewObject("ЖурналРегистрации")` НЕ работает; ЖР через COM не читать.
- Запись в регистр: НаборЗаписей → Отбор по всем измерениям → Добавить() → Записать(True).
