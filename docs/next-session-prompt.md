4. **Экономия токенов**: субагенту — узкий промт (файл/строка/что сделать/

## ЗАДАЧА 2 (АРМ-цепочка, по прямому указанию пользователя)

Пользователь: «забыл, какие АРМы должны запускаться ДО АРМ по отражению
выработки. Сейчас отрабатывает только АРМ по отражению заправок. АРМ по
отражению выпуска услуг и АРМ по отражению затрат растениеводства не
отрабатывают, и АРМ по отражению выработки не формирует выработку».

**Правильная цепочка АРМ-этапов (порядок обязателен, данные зависят
друг от друга в рамках одного периода)**:
1. АРМ по отражению заправок (arm-fuel-receipt / arm-fuel-expense) —
   заправки/расход ГСМ;
2. АРМ по отражению выпуска услуг — НЕ отрабатывает (шаблона нет или
   фейлится — выяснить);
3. АРМ по отражению затрат растениеводства — НЕ отрабатывает (то же);
4. АРМ по отражению выработки (arm-payroll) — сейчас PASS как
   «сценарий», но выработку НЕ формирует, т.к. нет входных данных от
   этапов 2–3 (и, возможно, 1) за тот же период.

Сделать:
1. **Инвентаризация**: какие АРМы есть в базе (справочник АРМов
   АпкАРМ*, см. fixtures armPlan) и какие шаблоны есть
   (`tests/templates/arm-*.feature` + coverage-map); каких не хватает
   (выпуск услуг, затраты растениеводства). Улики — в отчёт.
2. **Создать недостающие шаблоны** (arm-services-output,
   arm-plant-costs — имена по фактическим АРМам) по образцу
   arm-fuel-expense/arm-payroll: период `{{period.start}}/{{period.end}}`,
   сброс фильтра организаций, "ФормаОтформатироватьВсе" и т.п.
   (образец примитивов — в существующих шаблонах; форм-дискавери —
   зонды как в T4, если элементы отличаются).
3. **Порядок выполнения**: обеспечить в прогоне цепочку
   заправки → выпуск услуг → затраты растениеводства → выработка
   (внутри батча порядок фич = порядок манифеста; проверить, как
   препроцессор упорядочивает АРМ-фичи, при необходимости задать
   порядок в манифесте/патчах). АРМы, вероятно, выполняются под одним
   пользователем — тогда цепочка внутри одного батча идёт последовательно.
4. **Верификация живым прогоном**: полная цепочка за период ноября
   ({{period.start}}/{{period.end}}) → АРМ выработки формирует
   документ ВыработкиСотрудников с заполненными данными (не пустой).
   Проверить в базе (COM-зонд/запрос), что выработка реально создана.
5. Отчёт: состав АРМов, что было/что добавлено, порядок, вердикт
   цепочки — в night-report; шаблоны + патчи + coverage-map — в коммит.

Расследование форм АРМов (дискавери) — субагенты последовательно,
квантованные модели вормсофт; шаблоны-примитивы — сам по образцу.
