## Сопоставление «пользователь ↔ сценарии»

Для каждого найденного документа фиксируем: `Автор` (Справочник.Пользователи)
→ соответствие пользователю ИБ (в ERP пользователи ИБ связаны со справочником
Пользователи) → план прогонов: пользователь гоняет сценарии по типам
документов, автором которых он является. Хэш пароля: см. product.md
(`СохраняемоеЗначениеПароля`).

## Форма данных прогона (fixtures.json, генерирует препроцессинг)

```
{
  "runId": "2026xxxx-hhmm",
  "filters": {"organization": "...", "period": [...], "docTypes": [...]},
  "common": {"organization": "...", "subdivision": "...", "warehouse": "..."},
  "users": [{"ibUser": "...", "sourceAuthor": "...", "docTypes": [...]}],
  "documents": [{"type": "АпкПутевойЛистТракториста", "ref": "...",
                  "data": {шапка + ключевые ТЧ-строки}, "author": "..."}]
}
```

Шаблоны сценариев (`tests/templates/NN-*.feature`) подставляют: имена форм —
синонимы из метаданных; данные — из `documents[].data`; пользователя прогона —
из `users[]` (через КлиентыТестирования VAParams).
