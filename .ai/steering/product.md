## Что это

**Установочный комплект на языке 1С:Предприятия** для регрессионной
проверки функционала **растениеводства** модуля «АПК 2.5» для 1С:ERP.
Основной сценарий использования: обновили релиз ERP/АПК на тестовой
базе → инженер запустил препроцессор → запустил раннер → получил отчёт
в своей сессии 1С: что работает, что сломалось, что регрессировало.

## Целевая архитектура (обязательные ограничения)

1. **Препроцессор** написан на языке 1С:Предприятия; запускается под
   пользователем с правами администратора **в сеансе тестируемой базы**;
   готовит данные для тестов.
2. **Раннер** написан на языке 1С:Предприятия; запускается под
   пользователем с правами администратора в сеансе тестируемой базы;
   запускает тесты по подготовленным данным.
3. **Итоговый отчёт** формирует раннер и показывает **в сессии
   1С:Предприятия, откуда запускался** (форма/табличный документ, не
   внешние md/json-файлы).
4. **В рабочем процессе нет python, COM и LLM.** Всё между «запустил» и
   «увидел отчёт» — только язык 1С и Vanessa Automation. Python/COM/LLM
   допустимы только как dev-time инструментарий разработки (не входят
   в комплект и не участвуют в прогоне).
5. **Сервер и лицензии не исследуются и не обслуживаются комплектом.**
   Исправный сервер, живые лицензии, дамп/откат базы, свободные сеансы —
   задача инженера, который запускает. Комплект поставляет инструкцию
   (что обеспечить), а не автоматизацию этого.
6. **Состав установочного комплекта**: только скрипты на языке
   1С:Предприятия — препроцессор (EPF), раннер (EPF), Vanessa Automation
   single (EPF) — и сценарии Vanessa (`.feature`). Ничего больше.

## Ключевая идея

Тесты работают на **уже введённых** документах базы (не создают данные с нуля):
препроцессинг находит реальные путевые листы, наряды, заправочные ведомости,
взвешивания и извлекает из них элементы заполнения сценариев (организация,
подразделение, номенклатура, техника, ответственные, пользователи-авторы).
Сценарии выполняются **под правами реальных пользователей** — авторов
документов.

## Механизм паролей (без знания паролей пользователей)

Платформа 8.5: `ПользовательИнформационнойБазы.СохраняемоеЗначениеПароля`
(чтение + запись, администратор) + `ТипАлгоритмаХешированияПароля`.
Препроцессинг: сохранить хэш → установить тестовый пароль → прогнать
сценарии под пользователем → восстановить хэш (в т.ч. в обработке отказа).

## Границы

- Препроцессинг и раннер запускаются **только от администратора**.
- Хэши паролей — только средствами языка 1С (без SQL, без прямого доступа к СУБД).
- База-цель по умолчанию: `dev_erpapk_demo` (localhost, PostgreSQL).
  Решение должно быть переносимо на другую тестовую базу после обновления.
- Скоуп релиза 1 — документы растениеводства (глава 1 документации АПК).
- Инфраструктура (сервер, RAS/rac, лицензии, дамп/откат, сеансы) — **вне
  комплекта**; комплект содержит инструкцию инженеру.
- Вики по АПК хранится в одном месте: `c:\MyProjects\LLMWiki\APK`
  (сюда — только ссылки). Вики по Vanessa — `c:\MyProjects\LLMWiki\Vanessa-Automation`;
  в репозитории проекта её больше нет (в `wiki/` — только README-заглушка).
  Обе вики обновляются (ingest/query/lint) в LLMWiki.
