## Волна 2 — Диагностика ошибок (P1)

### T-201 — Контекст ошибки в 6 местах (путь файла + причина)

**Тип:** fix | **Приоритет:** P1 | **Замечания:** CR-01, CR-04

**Факт (проверено):** `ВызватьИсключение;` без параметров — это **перевыброс**, он сохраняет
`ИнформацияОбОшибке` и стек. Тезис ревью «теряется причина, админ видит пустое сообщение»
**ложен**: верхний уровень форм уже печатает `ПодробноеПредставлениеОшибки`
(препроцессор `Module.bsl:37` и др.). Реальный пробел — в тексте **нет имени файла**, а файлов
в прогоне много.

**Адреса (ровно 6, не 3 как в ревью):**
| Файл | Строки | Функции |
|---|---|---|
| `ObjectModule.bsl` | 1373 | `ПрочитатьJSONФайл` |
| `ObjectModule.bsl` | 1387 | `ЗаписатьJSONФайл` |
| `ObjectModule.bsl` | 3711 | `ТекстJSONСтрокой` |
| раннер `Module.bsl` | 882 | чтение файла выделения |
| раннер `Module.bsl` | 1132 | `Сервер_ПрочитатьBaseline` |
| раннер `Module.bsl` | 1163 | `Сервер_ЗаписатьBaseline` |

**Что делать — точный паттерн (НЕ так, как в v1):**

В v1 предлагалась `Процедура ОбработатьОшибку(...)` с телом из одного блока `Исключение`. Это
**невалидный BSL** (`Исключение` вне `Попытка … КонецПопытки` не компилируется), плюс
`&НаСервереБезКонтекста` в объектном модуле недопустима (директив в нём нет вообще), плюс
`ИнформацияОбОшибке()` внутри вложенной `Попытка` опишет пустое исключение.

Правильно — **оставить `ВызватьИсключение` в самом обработчике**, добавив контекст:

```bsl
Функция ПрочитатьJSONФайл(Путь)

	Результат = Неопределено;
	Чтение = Новый ЧтениеJSON;
	Попытка
		Чтение.ОткрытьФайл(Путь);
		Результат = ПрочитатьJSON(Чтение);
	Исключение
		ИнформацияОшибки = ИнформацияОбОшибке();
		Попытка
			Чтение.Закрыть();
		Исключение
			// сбой Закрыть() не должен подменять исходную ошибку
		КонецПопытки;
		ВызватьИсключение НСтр("ru = 'Не удалось прочитать JSON-файл: '") + Путь
			+ Символы.ПС + ПодробноеПредставлениеОшибки(ИнформацияОшибки);
	КонецПопытки;
	Чтение.Закрыть();
	Возврат Результат;

КонецФункции
```

То же по остальным 5 адресам: `НСтр("ru = '...: '") + <путь>` + `Символы.ПС` +
`ПодробноеПредставлениеОшибки(ИнформацияОшибки())`, где `ИнформацияОшибки` снимается **до**
закрытия ресурса.

**Критерии приёмки:**
- [ ] Битый JSON → сообщение содержит путь файла и причину
- [ ] `bsl-ls` 0 Error, compile-gate PASS
- [ ] `00-smoke` под админом по-прежнему PASS (поведение при валидных данных не изменилось)

**Время:** 1–2 ч

## Волна 3 — Устойчивость данных (P1)

### T-301 — Whitelist имён документов перед подстановкой в запрос

**Тип:** fix | **Приоритет:** P1 | **Замечание:** M-02

**Факт:** `ObjectModule.bsl:1521-1531` — ключ карты конкатенируется в текст запроса
(`" ИЗ Документ." + ТипДокумента`) без проверки. Параметризовать имя таблицы в языке запросов
нельзя. Посылка ревью про «внешний недоверенный источник» **ложна** (карта версионируется в
комплекте), но невалидное имя даёт платформенное исключение вместо понятного пропуска.

**Что делать:** в цикле перед сборкой текста запроса:
```bsl
Если Метаданные.Документы.Найти(ТипДокумента) = Неопределено Тогда
	// пропуск с записью в Предупреждения
	Продолжить;
КонецЕсли;
```
Способ уже применяется в этом же модуле — `ObjectModule.bsl:2362`
(`Метаданные.Документы.Найти`). **Не** вводить `Справочники.ДокументыКарта` (объекта не существует,
v1 предлагала именно его) и **не** использовать `ДокументыКарта.Свойство(...)` как проверку —
это тавтология (ключ берётся из того же Соответствия, всегда Истина).

**Критерии приёмки:**
- [ ] Несуществующий тип в карте → пропуск + предупреждение, прогон не падает
- [ ] Валидная карта → скан даёт тот же результат, что до правки

**Время:** 1–2 ч
