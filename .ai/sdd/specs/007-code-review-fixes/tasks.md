### T-07-001 — Exception-паттерн: потеря `ИнформацияОбОшибке` (CR-01, CR-04)

**Тип:** fix  |  **Приоритет:** P0

**Проблема:** `ВызватьИсключение` без параметров в `ПрочитатьJSONФайл`, `ЗаписатьJSONФайл`, `Сервер_ЗаписатьBaseline` — теряется причина сбоя и стек вызовов. При битом JSON/правах доступа/переполнении диска админ видит пустое сообщение.

**Описание изменений:**
1. Создать приватную процедуру `ОбработатьОшибку(Сообщение, Источник = "")` с шаблоном:
   `НСтр("ru = «" + Сообщение + "») + Символы.ПС + (Источник ? "Источник: " + Источник : "") + Символы.ПС + "Причина: " + ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`.
2. Найти все `Исключение ... ВызватьИсключение;` в `ObjectModule.bsl` и `ModuleForm.bsl` (форме) — их ~3 явных + обёртки `ПрочитатьJSONФайл`/`ЗаписатьJSONФайл`.
3. Заменить на вызов `ОбработатьОшибку("...", "ИмяМетода")`.
4. Добавить в `Сервер_ПрочитатьBaseline` / `Сервер_ЗаписатьBaseline` тот же шаблон.

**Критерии приемки:**
- [ ] `bsl-ls` → 0 ошибок, `v8std` → 0 нарушений
- [ ] compile-gate (ПодключитьВнешнюю + ПолучитьФорму) PASS
- [ ] `db-load-xml` в dev_erpapk_demo → без ошибок
- [ ] Round-trip выгрузка-загрузка → diff = 0
- [ ] Битый JSON → явное сообщение: имя файла + "Источник: Метод" + "Причина: ..."
- [ ] `00-smoke` под админом → PASS

**File targets:** `src/АпкПодготовкаСценарныхТестов/Ext/ObjectModule.bsl`, `src/АпкРаннер/.../Form/Module.bsl`, `tests/unit/server/test_json_error_handling.bsl`

**Время:** ~1–2 часа

### T-07-002 — Криптографически стойкий тестовый пароль (CR-03)

**Тип:** fix  |  **Приоритет:** P0

**Проблема:** `ГенераторСлучайныхЧисел()` без seed → предсказуемый пароль (зависит от системного времени); 20-символьный алфавит содержит похожие символы (I/l/1, O/0).

**Описание изменений:**
1. `СгенерироватьТестовыйПароль()`: `Новый ГенераторСлучайныхЧисел(Новый UUID())` вместо безаргументного.

4. Добавить `vaparamsTTLHours=24` в `preprocessor-settings.json` + фоновая задача при старте прогона (очистка `params/vaparams-*.json` старше TTL).

**Критерии приемки:**
- [ ] 2 подряд идущих батча → разные пароли
- [ ] В алфавите отсутствуют I/l/1, O/0 (проверить в тесте)
- [ ] `ЗавершитьБатч` восстанавливает хэш пароля при любом исходе (done/timeout/aborted/kill)
- [ ] `params/` добавлен в `.gitignore`
- [ ] E2E smoke PASS, `mismatch=[]`

**File targets:** `ObjectModule.bsl`, `preprocessor-settings.json`, `.gitignore`, `tests/unit/server/test_password_generation.bsl`

**Время:** ~1–2 часа

### T-07-003 — UTF-8 имена элементов форм → ASCII + escape-сущности (CR-02)

**Тип:** fix  |  **Приоритет:** P0

**Проблема:** имена элементов в `Form.xml` записаны сырым UTF-8 в атрибутах `name`/`DataPath` без escape-сущностей (стандарт 1С предписывает ASCII + escape). Риск непереносимости между версиями платформы/инструментами.

**Описание изменений:**
1. `form-info` на `src/АпкПодготовкаСценарныхТестов/Forms/Форма` + `src/АпкРаннер/.../Form.xml` — определить, какие имена кириллические.
2. Если кириллические имена найдены: переименовать элементы в ASCII (`ПолеПрогонов`, `КнопкаЗапустить`, `КнопкаОстановить`, ...), приведя модуль формы к ASCII-идентификаторам. Поэтапно, по 5–10 элементов за change-set.
3. Если имена уже латинские — замечание снимается (зафиксировать в report).
4. `form-validate` + round-trip выгрузка-загрузка → diff = 0; compile-гейт с скомпилированной формой.

**Критерии приемки:**
- [ ] `form-info` + `form-validate` без предупреждений о кодевании
- [ ] Round-trip diff = 0
- [ ] Compile-гейт с формой PASS
- [ ] Все обращения к элементам формы в модуле используют ASCII-идентификаторы

**File targets:** `src/АпкПодготовкаСценарныхТестов/Forms/Форма/Ext/Form/Form.xml`, `src/АпкРаннер/.../Form.xml`, `.../Form/Module.bsl`

**Время:** ~2–4 часа (зависит от количества элементов)

### T-07-006 — Маппинг имён таблиц в `ВыбратьДокументы` (M-02)

**Тип:** fix  |  **Приоритет:** P1

**Проблема:** `ИЗ Документ." + ТипДокумента` — подстановка из JSON-карты напрямую в текст запроса. При внешнем источнике карты возможны невалидные имена таблиц.

**Описание изменений:**
1. Создать маппинг JSON-ключ → каноническое имя метаданных (например, через `Справочники.ДокументыКарта` или таблицу констант).
2. Перед вставкой проверять: `Если Не ДокументыКарта.Свойство(ТипДокумента, КаноническоеИмя) Тогда Предупреждение("Тип " + ТипДокумента + " не найден в карте документов") + Продолжить`.
3. Лог ошибки писать в `Предупреждения` (не падать, как у остальных skip).

**Критерии приемки:**
- [ ] Несуществующий тип → skip с предупреждением, прогон не падает
- [ ] Валидный тип → запрос выполняется как раньше

**File targets:** `ObjectModule.bsl`

**Время:** ~1–2 часа

**Критерии приемки:**
- [ ] `maxRetryDuplicates=1000` из настроек (дефолт)
- [ ] `test_duplicate_catalog_guard` PASS: генерация 105 дублей → 104 предупреждения + последний успешен
- [ ] Уникальный ID в имени каталога
