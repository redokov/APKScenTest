## 1. Executive Summary

Аудит 23 замечаний код-ревью по фактическим исходникам показал: **критичных нет**,
1 замечание ложно полностью (M-01), 1 построено на ложной посылке (CR-02), 20 — частично верны
с ядром существенно мельче заявленного. План сокращён с 27 задач до **11** и сгруппирован
в 5 волн.

| Волна | Тема | Задачи | Оценка |
|---|---|---|---|
| 1 | **Переносимость** (единственное реально `major`) | T-101…T-104 | 6–9 ч |
| 2 | Диагностика ошибок (контекст: путь файла) | T-201 | 1–2 ч |
| 3 | Устойчивость данных | T-301…T-304 | 3–5 ч |
| 4 | Релиз (`dist/`, документация) | T-401, T-402 | 2 ч |
| 5 | Верификация (существующие гейты) | — | 1–2 ч |
| | **Итого** | **11** | **13–20 ч** |

**Ключевые решения v2:**
- Никаких новых инструментов: round-trip-скрипта, BSL-юнит-тестов и `--gherkin-lint` в проекте
  **нет** (проверено), поэтому они не могут быть гейтами.
- Единственная точка входа для путей — `tests/preprocessor-settings.json` + существующая
  функция `ПолныйПуть(Проект, Путь)` (`ObjectModule.bsl:1328`).
- Обработка ошибок — **перевыброс с контекстом** в самом обработчике, без процедуры-обёртки
  с блоком `Исключение` (v1 предлагала невалидный BSL).

## 2. Жёсткие ограничения

1. **Чистый 1С-комплект:** python/COM/LLM — только dev-time, не участвуют в прогоне
   (`.ai/steering/product.md:32-33, 44-46`). Вызов python из BSL на этапе прогона запрещён.
2. **Гейты BSL:** `bsl-ls` 0 Error и Warning ≤ 365 (baseline 06.11: 365 Warning / 167 Hint /

4. **Creds** — не коммитить; команда батча содержит `/P '<пароль>'`, поэтому **логировать её

   `tests/logs/` и `tests/run-*/`); `tests/preprocessor-settings.json` **закоммичен** — его правка
   (T-102) входит в объём работ.

### 3.1. Порядок работ и зависимости (исправлено)

В v1 утверждалось, что «T-07-001 блокирует все последующие правки, так как любое исправление
требует перезагрузки конфигурации в базе». **Это неверно:** правки BSL требуют compile-gate,
а `db-load-xml` нужен один раз перед E2E, не для каждой задачи.

Корректно:

1. **Волна 1** (T-101…T-104) — правит `ObjectModule.bsl`, препроцессор `Module.bsl`,
   раннер `Module.bsl` и настройки. Один change-set на файл.
2. **Волна 2** (T-201) — снова `ObjectModule.bsl` + раннер `Module.bsl`; выполняется **после**
   волны 1 (тот же файл).
3. **Волна 3** (T-301…T-304) — те же файлы; после волны 2.
4. `db-load-xml` — **один раз** после волны 3.
5. **Волна 4** (T-401) — пересборка `dist/` после прохождения гейтов.
6. **Волна 5** — E2E и ночной гейт.

Параллелить правки одного файла нельзя. Параллелить можно: `ObjectModule.bsl` (волны 1–3,
последовательно) и независимую документацию (T-402).

### 4.1. `tests/preprocessor-settings.json` — целевое состояние

48500→48000), и неверный `baselinePath: "base/baseline-real.json"` (каталога `base/` нет).

**Пояснения:**

### 4.2. Обработка ошибок — корректный паттерн (T-201)

**Удалён невалидный шаблон v1** (`Процедура ОбработатьОшибку` с телом из одного блока
`Исключение`):
- `Исключение` вне `Попытка … КонецПопытки` — синтаксическая ошибка;
- `КонецПроцедуры;` с точкой с запятой — невалидно;
- `&НаСервереБезКонтекста` в объектном модуле недопустима (директив в нём **0**);
- `ИнформацияОбОшибке()` во вложенной `Попытка` опишет пустое исключение — потеря причины.

**Также удалён** тернарный оператор из T-07-001 п.1 (`Источник ? "..." : ""`) — в BSL его нет.

Правильный паттерн — `ВызватьИсключение` остаётся в обработчике, добавляется контекст:

```bsl
Функция ПрочитатьJSONФайл(Путь)

	Результат = Неопределено;
	Чтение = Новый ЧтениеJSON;
	Попытка
		Чтение.ОткрытьФайл(Путь);
		Результат = ПрочитатьJSON(Чтение);
	Исключение
		ИнформацияОшибки = ИнформацияОбОшибке();
		Попытка
			Чтение.Закрыть();
		Исключение
			// сбой Закрыть() не должен подменять исходную ошибку
		КонецПопытки;
		ВызватьИсключение НСтр("ru = 'Не удалось прочитать JSON-файл: '") + Путь
			+ Символы.ПС + ПодробноеПредставлениеОшибки(ИнформацияОшибки);
	КонецПопытки;
	Чтение.Закрыть();
	Возврат Результат;

КонецФункции
```

**Важно:** `ПрочитатьJSON(Чтение)` — **без** второго аргумента. Второй параметр — это
`ПрочитатьВСоответствие`, а не «строгий разбор»; `Истина` вернула бы `Соответствие` вместо
`Структура` и сломала все 20+ чтений (см. §7, M-01).

### 4.3. Тестовый пароль — без изменений

Фикс v1 `Новый ГенераторСлучайныхЧисел(Новый UUID())` **невалиден**: конструктор принимает
Число, `УникальныйИдентификатор` к Числу не приводится, а `UUID` — англоязычное имя типа в
русском модуле. Задача снята.

Фактический алфавит (`ObjectModule.bsl:1056`) — 56 символов, похожие `I`, `l`, `1`, `O`, `0`
в нём **уже отсутствуют**; длина 20; пароль генерируется заново на батч. Реальный риск —
хранение пароля в открытом файле, и он закрывается TTL-очисткой (T-304), а не seed'ом.

### 4.4. Имена элементов форм — замечание отклонено

284 кириллических `name`-атрибута — штатная норма русских конфигураций (вся типовая ERP/АПК
такая). Оба `Form.xml` валидны как UTF-8, кодировка объявлена в прологе. Обработки собраны
**после** правки XML (`dist/*.epf` 03–04.11 vs XML 29.10/01.11) и формы открывались в GUI
(6 скриншотов в `dist/screenshots/`). Массовое переименование = регрессия ссылок (`DataPath`,
обработчики, обращения из модулей) и конфликт с требованием byte-идентичности при выгрузке.

Остаточный инструментальный риск (внешний редактор в CP1251 испортит файл) закрывается
дешёвым чеком кодировки, а не переименованием.

### 4.5. Относительный baseline (T-103, T-104)

**Удалён невалидный фрагмент v1**: он использовал необъявленную переменную `НастройкиПрогона`,
был помечен `&НаСервере` внутри объектного модуля и вызывал `НормализоватьПуть`, которая
относительные пути **не** резолвит (`ObjectModule.bsl:1316` — только нормализует разделители).

Резолв относительного пути уже реализован — `ПолныйПуть(Проект, Путь)` (`ObjectModule.bsl:1328`),
его и использовать. Раннер — отдельный ERF, функций препроцессора не видит, поэтому ему нужен
**собственный** загрузчик настроек (этого не было в v1).

Отдельно (T-104): сейчас при ошибке чтения baseline `АпкРаннер/.../Module.bsl:614-621` делает
`Базовые = Неопределено` и прогон продолжается — отчёт выглядит зелёным, хотя сравнение
**не выполнялось**. Нужны три различимых состояния: прочитан / задан но не читается
(`baseline: ERROR` + причина) / не задан (`n/a`).

## 9. FAQ

**Q: Почему задача M-01 (strict JSON) снята?**
A: Второй параметр `ПрочитатьJSON` — `ПрочитатьВСоответствие`, а не строгость. Контроля
дубликатов ключей в платформе нет. Применение `(Чтение, Истина)` в общем `ПрочитатьJSONФайл`
вернуло бы `Соответствие` вместо `Структура`, и 8 guard'ов `Тип("Структура")`
(`ObjectModule.bsl:23, 91, 434, 588, 1091, 1959, 2300, 3512`) начали бы кидать исключения, а
`ЗначениеСвойства` — молча отдавать умолчания.

**Q: Почему не переименовываем кириллические имена элементов?**
A: Это норма, а не дефект; обработки собраны и открываются. Переименование 284 имён = регрессия
ссылок в модулях и `Form.xml`.

**Q: Почему не заменяем `ping` на `Сон`?**
A: `Сон(Секунд*1000)` даёт паузу в 1000 раз длиннее (2 с → 2000 с), а критерий «±50 мс»
противоречит самому фиксу. Метод `Сон` в кодовой базе не используется ни разу; в комментарии
кода зафиксировано, что в клиентском BSL функции сна нет.

**Q: Что делать с S-05 и S-08?**
A: В исходном ревью их текста нет (grep по всем документам = 0). Считать неопределёнными;
при необходимости — спека 008 с исходным текстом ревью.

**Q: Сколько реально сделать за ночь?**
A: По истории проекта — 1–2 change-set'а за сессию. Поэтому волны 1–3 (11 задач → 3 change-set'а)
и гейты 1–2 — целевой минимум; E2E и ночной гейт — по остатку времени.
