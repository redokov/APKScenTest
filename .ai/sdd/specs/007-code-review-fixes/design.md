> **Requirements:** @requirements.md
> **Status:** draft — к утверждению пользователем

## 1. Executive Summary

Устранение замечаний код-ревью кодовой базы «АпкПодготовкаСценарныхТестов» (~5039 строк BSL: препроцессор `ObjectModule.bsl` 3840 строк, раннер «АпкРаннер» 1199 строк) разбито на **4 приоритета** и **29 задач (T-07-001…T-07-027)**:

| Приоритет | Замечания | Задачи | Цель |
|---|---|---|---|
| **P0** | CR-01…CR-05 (критичные) | T-07-001…T-07-004 | Блокирующие релиз: безопасность паролей, переносимость, потеря ошибок |
| **P1** | M-01…M-08 (серьёзные) | T-07-005…T-07-012 | Устойчивость в CI, безопасность запросов, детерминизм |
| **P2** | S-01…S-10 (нормальные) | T-07-013…T-07-019 | Чистота кода, архитектура, снижение стоимости поддержки |
| **P3** | тестовое покрытие | T-07-020…T-07-027 | Гарантия отсутствия регрессий |

**Ключевые решения:**
- Единый шаблон обработки ошибок `ОбработатьОшибку(Сообщение, Источник)` вместо пустого `ВызватьИсключение`.
- Криптографически стойкий пароль: `Новый ГенераторСлучайныхЧисел(Новый UUID())`, seed из UUID + алфавит без похожих символов.
- ASCII-имена элементов форм + escape-сущности в XML для переносимости.
- Относительный путь к baseline из `preprocessor-settings.json`.
- Probe порта ПЕРЕД выделением + стабильная сортировка АРМов.
- Тесты — dev-time зона (`tests/unit/`, `tests/pytest/`, `tests/scenarios/`), не входят в комплект.

## 2. Требования к архитектуре (жёсткие ограничения)

1. **Чистый 1С-комплект:** python/COM/LLM — только dev-time инструментарий, не входят в комплект и не участвуют в прогоне (`.ai/steering/product.md`, спека 005).
2. **Гейты качества BSL** (после любой правки, до загрузки в базу): `bsl-ls MCP bsl_analyze` (0 ошибок) → `v8std MCP` (0 нарушений) → compile-gate (Подключить+ПолучитьФорму).
3. **Кириллица в CLI** — только через билдеры `scripts/build_cyrillic.py`.
4. **Пароли/creds** — не коммитить (`.gitignore`: `tests/run-*/`, `.env`, `heartbeat/`, `.its_creds.txt`).
5. **Тесты** — в `tests/`, который уже в `.gitignore`; не собираются в `dist/`.

### 3.1. Зависимости между задачами

1. **T-07-001 (CR-01/CR-04 — exception-паттерн)** — **блокирует** все последующие правки, так как любое исправление требует перезагрузки конфигурации в базе. Запускается первым: `db-load-xml` → compile-gate → round-trip.
2. **T-07-002 (CR-03 — пароль)** — влияет на `Сервер_ЗаписатьVAParams` / `ЗавершитьБатч`; делать после T-07-001 (единообразный change-set).
3. **T-07-003 (CR-02 — UTF-8 форм)** — зависит от скомпилированной формы; делать после сборки EPF.
4. **T-07-004 (CR-05 — хардкод пути)** — зависит от `preprocessor-settings.json`; независим от базы.
5. **P1 задачи** — можно выполнять параллельно, группируя по объектам (`ObjectModule.bsl` / `ModuleForm.bsl` / настройки).
6. **P2/P3** — чистота + тесты, не блокируют релиз.

### 4.2. Единый шаблон обработки ошибок (T-07-001)

```bsl
// ObjectModule.bsl — в области ВспомогательныеФункции
&НаСервереБезКонтекста
Процедура ОбработатьОшибку(Сообщение, Источник = "")
	// НСтр — локализация, Источник — где ошибка произошла,
	// ПодробноеПредставлениеОшибки — причина + стек.
	Исключение
		Сообщ = НСтр("ru = «" + Сообщение + "»");
		Если Не ПустаяСтрока(Источник) Тогда
			Сообщ = Сообщ + Символы.ПС + "Источник: " + Источник;
		КонецЕсли;
		Сообщ = Сообщ + Символы.ПС + "Причина: " + ПодробноеПредставлениеОшибки(ИнформацияОбОшибке());
		ВызватьИсключение Сообщ;
	КонецПроцедуры;
```

Использование:

```bsl
Функция ПрочитатьJSONФайл(Путь)

	Чтение = Новый ЧтениеJSON;
	Чтение.ОткрытьФайл(Путь);
	Попытка
		Результат = ПрочитатьJSON(Чтение, Истина);  // M-01: strict-режим
	Исключение
		Чтение.Закрыть();
		ОбработатьОшибку("Не удалось прочитать JSON-файл " + Путь, "ПрочитатьJSONФайл");
	КонецПопытки;
	Чтение.Закрыть();
	Возврат Результат;
КонецФункции
```

### 4.3. Криптографически стойкий пароль (T-07-002)

```bsl
Функция СгенерироватьТестовыйПароль() Экспорт

	// Seed из UUID — непредсказуем даже при известном времени запуска.
	// БСП ГенераторПаролей — fallback, если доступен.
	Генератор = Новый ГенераторСлучайныхЧисел(Новый UUID());
	Пароль = "";
	Для Ном = 1 По 20 Цикл
		Пароль = Пароль + Сред(Алфавит, Генератор.СлучайноеЧисло(1, СтрДлина(Алфавит)), 1);
	КонецЦикла;
	Возврат Пароль;
КонецФункции
```

Алфавит исключает похожие символы: `I/l/1`, `O/0`, `S/5`, `g/6`.

**Хранение VAParams (M-06/M-08):** пароль живёт в `params/vaparams-*.json` только во время батча; `finally` в `ЗавершитьБатч` удаляет его + фоновая задача чистит старше TTL=24ч. При желании — опциональное шифрование через криптокомпоненту (не блокирует прогон).

### 4.4. Имена элементов форм (T-07-003)

Текущее состояние: имена элементов в `Form.xml` записаны сырым UTF-8 в атрибутах `name`/`DataPath` (например, `<InputField name="КаталогПрогона"...>`), **без** escape-сущностей и ASCII-псевдонимов.

Решение:
1. Переименовать элементы в ASCII (`КаталогПрогона` → `ПолеПрогонов`... — по согласованию), приведя модуль формы в соответствие.
2. В XML оставить ASCII-имена + escape-сущности для кириллических заголовков/подсказок.
3. `form-validate` + round-trip выгрузка-загрузка → diff = 0.

Если проверка `form-info` покажет, что текущие имена уже латинские — замечание снимается.

### 4.5. Относительный путь baseline (T-07-004)

```bsl
&НаСервере
Функция Сервер_ПолучитьПутьBaseline(ПутьКаталогаПроекта) Экспорт

	Относительный = ЗначениеСвойства(НастройкиПрогона, "baselinePath", "base/baseline-real.json");
	Возврат НормализоватьПуть(СтрСоединить(ПутьКаталогаПроекта, "/", Относительный));
КонецФункции
```

`ПриСозданииНаСервере` формы раннера: брать `baselinePath` из настроек + предупреждение, если не задан (вместо хардкода `C:/MyProjects/...`).

### 5.2. Новый приватный интерфейс (ObjectModule.bsl)

- `ПараметрыПрогона()` — читает/валидирует `preprocessor-settings.json` с дефолтами (pre-load validation, FR-004).
- `ОбработатьОшибку(Сообщение, Источник)` — единый шаблон (T-07-001).
- `ЗанятПорт(Порт)` — client-side probe (Connect) + опционально Win32_Process (M-04).
- `ПланАРМовСтабильный(ПланАРМов)` — двойная сортировка: `arm+user` → `scenario` (M-07).
- `ЛинтGherkin(КаталогФич)` — вызов dev-time хелпера `python scripts/t8_gate.py --gherkin-lint`, результат в `Предупреждения` (S-09).
- `Кавычки(Значение)` — единая обёртка `"" + Строка + ""` (S-01).

### 5.3. Изменения в раннере (AпкРаннер/Ext/Form/Module.bsl)

- `Сервер_ПрочитатьBaseline` / `Сервер_ЗаписатьBaseline` — паттерн `ОбработатьОшибку` (T-07-001).
- `ЗначениеИзСоответствияСрв` — `Null` → `""` (S-04).
- `Сервер_ПолучитьПутьBaseline` — относительный (T-07-004).

## 6. Потоки (Flows)

### 6.1. Поток исправления кода (единый change-set)

```
1. bsl-ls (синтакс/стандарты) → 0 ошибок
2. v8std (стандарты фирмы 1С) → 0 нарушений
3. bsl-compile (compile-gate: ПодключитьВнешнююОбработку + ПолучитьФорму)
4. db-load-xml в dev_erpapk_demo (агентный режим, без сеансов)
5. round-trip: выгрузить XML в НОВЫЙ каталог → diff → 0 изменений
6. запуск unit-тестов (tests/unit/, тестовая база)
7. E2E smoke: 00-smoke под админом → PASS
8. ночной гейт s00X: 16/16 (растениеводство) + neg-1 → зелёный, rs=0
9. коммит + обновить tasks.md, evidence docs/
```

### 6.2. Поток ночного автономного прогона

```
PRE:  C: свободно ≥10 ГБ, база доступна, RAS/rac — админ, десктоп idle
HEARTBEAT: tmp/<prefix>/heartbeat.txt каждые 30 мин, строка «YYYY-MM-DD HH:MM:SS <этап>»
STEPS:
 1. t8_gate.pre_flight() — COM-чек базы, отсутствие сеансов (кроме RAS)
 2. restore базы в исходное состояние (если был --update)
 3. запуск препроцессора под Администратором (EPF)
 4. генерация сценариев + gherkin lint (dev-time хелпер)
 5. запуск раннера: батчи под авторами + neg-батч; таймаут 25 мин/батч
 6. финализация: восстановление хэшей паролей (finally), mismatch=[]
 7. запись вердикта: docs/night-report-<date>-s<id>.md
 8. update baseline (если --set-baseline), регресс vs baseline-real.json (rs=0)
 9. откат базы (restore previous dt) — всегда, даже при ошибке
 10. continuation: docs/next-s<id+1>-prompt.md, если не завершено
```

## 7. Edge cases

| Случай | Обработка (текущая) | Требуемое улучшение | Задача |
|---|---|---|---|
| Битый JSON-файл (фикстура/план) | теряется `ИнформацияОбОшибке` | явное сообщение: файл + причина + стек | T-07-001 / M-01 |
| Пароль пользователя совпадает с тестовым | нет проверки | сравнивать `СохраняемоеЗначениеПароля` — если совпал, предупредить | T-07-002 |
| Порт занят осиротевшим TestClient | `УбратьОсиротевшихTestClient` ПОСЛЕ конфликта | probe ПЕРЕД выделением; авто-откат +1 | T-07-008 |
| `ВыбратьДокументы` с несуществующим типом | ошибка платформы, прогон падает | маппинг → `Предупреждение` + skip | T-07-006 |
| `Неопределено` из `Сервер_ПланПрогона` | клиентская ошибка при цикле | `ТипЗнч(...)=Тип("Массив")`-guard | T-07-009 |
| Дубликаты сценарных ID | `>50` → краш | `maxRetryDuplicates=1000` + ID-суффикс | T-07-007 |
| Прогон прерван kill/timeout | `params/vaparams-*.json` остаётся | фоновая очистка по TTL (24ч) | T-07-010 |
| UTF-8 имена в форме на старой платформе | потенциально не загрузится | ASCII-имена + escape-сущности | T-07-003 |
| Параллельные прогоны в `tmp/` | риск коллизии | уникализировать `tmp/<user>-<runid>` | T-07-007 |
| `Null` в JSON-структуре | «null» в фикстуре | `Null|Неопределено → ""` | T-07-009 / S-04 |

## 8. Риски

| Риск | Вероятность | Влияние | Митигация | Ответственный |
|---|---|---|---|---|
| XML-формы содержат кириллические реквизиты (не ASCII) → большой change-set | Высокая | Серьёзное | Сначала `form-info` + `form-validate`; поэтапно по 5–10 элементов | разработчик |
| `ГенераторПаролей` БСП недоступен в 8.5.4.1683 | Средняя | Средняя | `UUID()`-seed как основной fallback | разработчик |
| `bsl-ls`/`v8std` гейты не работают (как баг Python 3.11 UTF-8) | Средняя | Низкая (dev-time) | обход через билдеры + ручная валидация; зафиксировать в PLAN | архитектор |
| Контент ревью не полностью воспроизведён в специке | Низкая | Низкая | ссылки на нумерацию CR/M/S; при необходимости — спека 008 «Code Review Detail» | архитектор |
| Нарушение чистоты комплекта (python попадает в прогон) | Низкая | Критическое | `t8_gate.py` check: `scan BSL for "regress_run" / os.system`; README-напоминание | архитектор |
| Компиляция формы ломается после переименования | Средняя | Средняя | compile-gate после каждого change-set; round-trip diff | разработчик |

## 9. FAQ

**Q: Почему тесты не входят в комплект?**
A: product.md (28.10.2026) возвращает цель к «чистому 1С-комплекту»; тесты — dev-time зона (`tests/`, `scripts/`), `gitignore`, не собираются в `dist/`. Это согласовано пользователем.

**Q: Можно ли хранить пароли зашифрованными?**
A: Да, опционально — через криптокомпоненту; но это усложняет dev-time запуск (нужен ключ). По умолчанию: открытый VAParams + TTL-очистка + `.gitignore`.

**Q: Нужна ли правка `ЗначениеИзСоответствия` в форме и в препроцессоре?**
A: Да, синхронизировать: обе функции одинаково обрабатывают `Null` → `""` (паритет с `ЗначениеФикстурыЗначения`).

**Q: Как проверить «сырой UTF-8» в форме без GUI?**
A: `form-info` + `form-validate` (MCP) покажут предупреждения; `db-dump-xml` + round-trip diff — byte-идентичность.

**Q: Сколько времени займёт весь объём (CR + M + S + тесты)?**
A: Оценивать по задачам после утверждения tasks.md; критичные (P0) — 1–2 сессии; P1 — 2–3; P2 + P3 — 3–4.

**Q: Что делать с `next-s<id>-prompt.md`?**
A: После каждой ночной сессии — `docs/next-sXXX-prompt.md` (рецепт продолжения); для новой эпика — `docs/night-prompt-<date>-007-fixes.md`.
