## Overview

**Внешние обработки 1С:Предприятия 8.5.4.1683:**
- `АпкПодготовкаСценарныхТестов` (EPF, препроцессинг): сканирование проведённых документов →
  фикстуры → генерация `.feature` для Vanessa Automation → менеджер тестовых паролей → план прогона.
- `АпкРаннер` (ERF, раннер): запуск прогона батчами, восстановление паролей, отчёт со сравнением
  против baseline.

**Что делает спека v2.** Устраняет **только те замечания, которые подтверждены аудитом как реальные
и важные**. Итог аудита по 23 замечаниям: критичных **нет**; `major` — 1 (CR-05, переносимость);
`minor` — 19; ложно полностью — 1 (M-01); ложная посылка с нулевой важностью — 1 (CR-02);
документальное — 1 (S-05/S-08). Косметика и ложно-положительные вынесены в `tasks.md`
§«Отклонено» с обоснованием.

**Целевая архитектура** (`.ai/steering/product.md`): всё между «запустил препроцессор» и
«увидел отчёт в 1С» — только язык 1С + Vanessa Automation. Python/COM/LLM — только dev-time,
не входят в комплект и не участвуют в прогоне.

## Business Context

- **Проблема:** комплект завязан на абсолютные пути, один из которых указывает в **чужой проект**
  (`vaEpfPath` → `C:\MyProjects\APKTechPlan\...`, файл закоммичен в git). При переносе на другую
  машину baseline не находится, ошибка его чтения **глушится**, и прогон выдаёт ложный «зелёный»
  результат без сравнения с эталоном. Это единственная реально серьёзная проблема.
- **Вторичное:** при сбое JSON-чтения в сообщении нет имени файла (диагностика); невалидный тип
  документа в карте даёт платформенное исключение вместо пропуска; в препроцессоре зачистка
  TestClient вызывается после старта; при внешнем kill остаётся `vaparams-*.json` с паролем.
- **Пользователи:** инженер по тестированию (запуск препроцессора и раннера под админом).
- **Сигнал успеха:** комплект работает из произвольного корня; отсутствие baseline даёт
  `baseline: ERROR`, а не ложный PASS; `00-smoke` PASS; `bsl-ls` 0 Error и Warning ≤ 365.

- **Отложено:** `M-03` (нереалистичный сценарий), `M-07` (не влияет на baseline),
  `CR-03` (алфавит уже без похожих символов; fix ломающий), `S-07` (замена `ping` на `Сон`
  ломает размерность), `S-09` (python из BSL запрещён).
- Изменение формата `fixtures.json` / `scan.json` — контракты спек 001/002 зафиксированы.

- Создание новых тестовых инструментов — в проекте нет ни round-trip-скрипта, ни инфраструктуры
  BSL-юнит-тестов; гейтами могут быть только существующие средства.

## User Stories

### US-001: Переносимость комплекта (единственный `major`)

**As a** инженер, я хочу собирать комплект в произвольный корень и переносить его между
машинами/десктопами **So that** не зависеть от `C:/MyProjects/...` и чужого проекта.

**Acceptance Criteria:**
- [ ] `grep -rn "C:/MyProjects\|C:\\\\MyProjects" src/` → 0 совпадений (T-101)
- [ ] `tests/preprocessor-settings.json`: валидный JSON, `projectDir` и `vaEpfPath` относительные,
      `vaEpfPath` указывает на файл внутри репозитория, `baselinePath` = `tests/baseline/baseline-real.json` (T-102)
- [ ] Раннер получает путь baseline из настроек (собственный загрузчик, т.к. ERF не видит
      функции препроцессора) (T-103)
- [ ] Отсутствие/битость baseline → в отчёте `baseline: ERROR` + причина, **не** ложный PASS (T-104)

### US-002: Диагностика ошибок

**As a** инженер, я хочу видеть в сообщении об ошибке имя файла и причину **So that** быстро
находить сбойный файл среди десятков.

**Acceptance Criteria:**
- [ ] В 6 местах перевыброса добавлен контекст: `ObjectModule.bsl:1373, 1387, 3711`;
      раннер `Module.bsl:882, 1132, 1163` (T-201)
- [ ] Паттерн: `ВызватьИсключение НСтр(...) + Путь + Символы.ПС + ПодробноеПредставлениеОшибки(ИнформацияОшибки())`;
      `ИнформацияОшибки` снимается **до** закрытия ресурса; сбой `Закрыть()` не подменяет исходную ошибку
- [ ] `ВызватьИсключение;` (перевыброс) сам по себе **не** является дефектом — `ИнформацияОбОшибке`
      сохраняется; критерий ревью «теряется причина / пустое сообщение» не подтверждён
- [ ] Поведение на валидных данных не изменилось (`00-smoke` PASS)

### US-003: Устойчивость к некорректным данным

**As a** инженер, я хочу, чтобы кривые данные комплекта давали пропуск с предупреждением, а не
падение **So that** прогон оставался диагностируемым.

**Acceptance Criteria:**
- [ ] Невалидный тип документа в карте → пропуск + предупреждение через
      `Метаданные.Документы.Найти()` (T-301)
- [ ] `null` в JSON-полях отчёта → `""`, отчёт строится (`Null`-guard в раннере) (T-303)
- [ ] Зачистка TestClient в препроцессоре вызывается **до** `Шелл.Exec` (T-302)

### US-004: Гигиена секретов

**As a** администратор тестовой базы, я хочу, чтобы тестовый пароль не оставался на диске после
прерванного прогона **So that** не копились файлы с секретом.

**Acceptance Criteria:**
- [ ] `vaparams-*.json` / `status-*.txt` / `batch-*/features` старше `vaparamsTTLHours` (24)
      в `tests/run-*/params` удаляются при старте прогона (T-304)
- [ ] Удаление в финализации на всех исходах **уже реализовано** (раннер `:483-486`,
      вызовы `:358, :374, :383, :390`) — не переписывать, только регресс-проверка
- [ ] Команда батча содержит `/P '<пароль>'` — **логировать её в открытом виде запрещено**

### US-005: Релиз

**As a** пользователь комплекта, я хочу получить пересобранные обработки и инструкцию по переносу.

**Acceptance Criteria:**
- [ ] `dist/АпкПодготовкаСценарныхТестов.epf` и `dist/АпкРаннер.epf` новее правок `src/` (T-401)
- [ ] В `dist/ИНСТРУКЦИЯ.md` есть раздел «Перенос комплекта на другую машину» (T-402)

### US-006: Гарантии качества — только существующие гейты

**As a** разработчик, я хочу, чтобы правки проверялись доступными средствами, а не выдуманными.

**Acceptance Criteria:**
- [ ] `bsl-ls` по `src/` → **0 Error**, Warning **≤ 365** (baseline 06.11: 365/167/164)
- [ ] compile-gate (`ПодключитьВнешнююОбработку` + `ПолучитьФорму`) PASS
- [ ] `db-load-xml` в `dev_erpapk_demo` без ошибок
- [ ] `00-smoke` под Администратором → PASS
- [ ] (если останется время) ночной гейт: 16/16 растениеводство + neg-1, `rs=0`, `mismatch=[]`
