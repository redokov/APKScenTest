# Feature: 007 — Code Review Fixes & Test Coverage (устранение замечаний код-ревью)

> **Статус:** draft — к утверждению пользователем
> **Источник:** итоговое код-ревью кодовой базы «АпкПодготовкаСценарныхТестов» (EPF препроцессор + EPF раннер «АпкРаннер», ~5039 строк BSL); замечания пронумерованы CR-01…CR-05 / M-01…M-08 / S-01…S-10
> **Жёсткие ограничения проекта:** целевая архитектура «чистый 1С-комплект» (спека 005, `.ai/steering/product.md`) — **python/COM/LLM остаются только dev-time инструментарием, не входят в комплект и не участвуют в прогоне**; все правки BSL проходят гейты `bsl-ls` + `v8std`; кириллица в CLI — только через билдеры `scripts/build_cyrillic.py`.

---

## Overview

**Внешние обработки 1С:Предприятия 8.5.4.1683:**
- `АпкПодготовкаСценарныхТестов` (EPF, препроцессинг): сканирование проведённых документов → фикстуры → генерация `.feature` для Vanessa Automation → менеджер тестовых паролей → план прогона.
- `АпкРаннер` (ERF, раннер): управляемая форма для запуска прогона батчами, восстановления паролей при любом исходе, отчёт со сравнением против baseline.

**Что делает спека 007.** Устраняет замечания код-ревью, сгруппированные по приоритетам:
- **P0 (критичные, CR-01…05):** потеря информации об ошибке при работе с JSON, сырой UTF-8 в именах элементов форм, предсказуемый тестовый пароль, хардкод абсолютного пути к baseline.
- **P1 (серьёзные, M-01…08):** strict-режим JSON, безопасная подстановка имён таблиц в запрос, устойчивость выделения каталога прогона и портов, обработка `Null`/`Неопределено`, детерминизм порядка АРМов, TTL-очистка `params/`.
- **P2 (нормальные, S-01…10):** вынос магических чисел, группировка кода по `#Область`, дубликаты обёрток, `ping` → `Сон`.
- **P3 (тестовое покрытие):** unit-тесты BSL (сервер + клиент), pytest-паритет python-эталона, E2E-гейты.

**Целевая архитектура** (согласно `product.md`): всё между «запустил препроцессор» и «увидел отчёт в 1С» — только язык 1С + Vanessa Automation. Python/COM/LLM допустимы **только как dev-time инструментарий разработки** (не входят в комплект и не участвуют в прогоне).

## Business Context

- **Проблема:** после ревизии кодовой базы выявлены риски: потеря отладочной информации при ошибках (блокирует диагностику), переносимость XML-исходников между версиями платформы, компрометация тестовых учётных записей (предсказуемый пароль), зависимость от жёстко заданного пути к baseline.
- **Пользователи:** инженер по тестированию (запуск препроцессора и раннера под админом).
- **Ценность:** устойчивый, отладочный, переносимый комплект, который не ломается при переносе на другую машину/десктоп.
- **Сигнал успеха:** все P0-задачи закрыты → compile-gate PASS → round-trip выгрузка-загрузка = 0 изменений → E2E smoke PASS → ночной гейт 16/16 + neg-1, `rs=0`.

## Goals

- Исправить все критичные (CR) замечания с доказательством E2E.
- Снизить риски средней тяжести (M) до приемлемого уровня: безопасность, устойчивость в CI, детерминизм.
- Улучшить архитектуру (S) для снижения стоимости поддержки.
- Добавить контур тестирования: unit (сервер/клиент), сценарные, pytest-паритет, baseline-гейты.
- Сохранить архитектурное ограничение спеки 005: тесты — dev-time зона (`tests/`, `scripts/`), не входят в `dist/`.

## Non-Goals / Out of Scope

- Переписывание бизнес-логики препроцессора (сохранять замёрзшие механизмы спеки 001 as-is, кроме явных исправлений).
- Изменение формата fixtures.json / scan.json (контракты зафиксированы специками 001/002).
- Внедрение python/COM в прогон (запрещено product.md).
- Создание GUI-инструментов — только форма раннера уже существует.

## User Stories

### US-001: Надёжная обработка ошибок

**As a** инженер по тестированию
**I want to** получать при ошибках название файла и причину сбоя, а не пустое сообщение
**So that** быстро локализовать, что сломалось (битый JSON, права доступа, переполнение диска)

**Acceptance Criteria:**
- [ ] `ПрочитатьJSONФайл` / `ЗаписатьJSONФайл` передают `ИнформацияОбОшибке()` + `НСтр("ru = ...")` в `ВызватьИсключение` (CR-01)
- [ ] `Сервер_ЗаписатьBaseline` использует тот же паттерн (CR-04)
- [ ] Строгий JSON (`ПрочитатьJSON(Чтение, Истина)`) — битый upstream-файл ругается явно (M-01)
- [ ] `Формат(Число, "ЧГ=")` везде, где число идёт в команду ОС (порт, PID) — нет NBSP-разделителей (M-04, S-10)

### US-002: Переносимость комплекта

**As a** инженер, я хочу, чтобы комплект собирался в произвольный корень и форматы переносились между версиями платформы
**So that** не зависеть от `C:/MyProjects/...` и запускать с разных десктопов/VM

**Acceptance Criteria:**
- [ ] Путь к baseline берётся из `preprocessor-settings.json` (относительный, относительно `projectDir`), хардкод `C:/MyProjects/...` удалён (CR-05)
- [ ] Имена элементов форм — ASCII + escape-сущности в XML, платформа 8.5.4.1683 загружает без ошибок (CR-02)
- [ ] Round-trip выгрузка-загрузка подтверждает byte-идентичность (CR-02, CR-04)

### US-003: Безопасность учётных записей

**As a** администратор тестовой базы, я хочу, чтобы тестовые пароли были непредсказуемыми, а хэши пользователей — аутентично восстановлены
**So that** никто не мог восстановить реальные пароли авторов и чтобы база после прогона работала как раньше

**Acceptance Criteria:**
- [ ] `СгенерироватьТестовыйПароль` использует криптографически стойкий генератор (seed из `UUID()`, исключены похожие символы I/l/1, O/0) (CR-03)
- [ ] Два подряд идущих батча дают разные пароли
- [ ] `ЗавершитьБатч` в `finally` восстанавливает хэш пароля; верификация повторным чтением (NFR-003/M-08)
- [ ] `params/vaparams-*.json` очищаются по TTL (24 ч) при kill прогона (M-06), файл в `.gitignore`

### US-004: Устойчивость в CI

**As a** инженер, я хочу, чтобы прогон не падал при интенсивных повторных запусках, конфликтах портов и некорректных данных
**So that** ночные гейты были детерминированными и восстанавливаемыми

**Acceptance Criteria:**
- [ ] Лимит дублей каталога прогона ≥ 1000 + суффикс уникальности (микросекунды/случайный 6-значный ID), предупреждение при > 100 (M-03)
- [ ] Проверка занятости порта ПЕРЕД выделением; авто-откат на следующий порт + предупреждение (M-04)
- [ ] `Null`/`Неопределено` → `""` во всех конвертерах (`ЗначениеИзСоответствия`, `ЗначениеИзСоответствияСрв`, `ФильтрВыделения`) (M-05, S-04)
- [ ] `ПланАРМов` — стабильная двойная сортировка (`arm + user` → затем `scenario`) (M-07)
- [ ] Необработанный `Неопределено` из `Сервер_ПланПрогона` guarded `ТипЗнч(...)=Тип("Массив")` (M-05)
- [ ] Имена типов документов маппятся из доверенной таблицы `ДокументыКарта` перед подстановкой в запрос (M-02)

### US-005: Качество кода и архитектура

**As a** разработчик, я хочу чистый поддерживаемый код
**So that** экономить время на онбординг и дальнейшие правки

**Acceptance Criteria:**
- [ ] Магические числа вынесены в `preprocessor-settings.json` с дефолтными значениями (`timeoutMinutesPerBatch=10`, `portBase=48000`, `maxTabularRows=3`, `passwordAlphabet`) (S-02)
- [ ] Приватные функции сгруппированы по `#Область` (ВспомогательныеФункции, РаботаСJSON, ПатчиСценариев, ГенерацияФич, Фикстуры) (S-03)
- [ ] Единая обёртка кавычек `Кавычки` (S-01)
- [ ] `ПаузаКлиента` заменён на `Сон(Секунд*1000)` (S-07)
- [ ] Полная команда батча собирается в `Массив` + `СтрСоединить(" ", ...)` и логгируется (S-10)
- [ ] Явно указано в заголовках методов, что работает только в неограниченном режиме безопасности (COM, shell, файл) (S-06)
- [ ] Gherkin lint-гейт на этапе `ПодготовитьПрогон` (S-09)

### US-006: Тестовое покрытие

**As a** инженер, я хочу гарантию, что исправления не вносят регрессий
**So that** выпускать правки уверенно

**Acceptance Criteria:**
- [ ] Unit-тесты BSL: `ОтсортироватьПланАРМовПоЦепочке` (детерминизм на 3+ перестановках), `ЗначениеИзСоответствия` (Null/Неопределено/числа/строки/массивы), `ОбработатьОшибку` (содержимое исключения), генерация пароля (уникальность)
- [ ] Клиентский unit: `Сон` vs `ping` (тайминг ±50 мс)
- [ ] pytest: паритет `regress_run.py` (python ↔ 1C-раннер) — план и вердикт совпадают; gherkin lint на всех `.feature`
- [ ] E2E-гейт: ночной прогон (16/16 растениеводство + neg-1) → `rs=0` vs `baseline-real.json`, `mismatch=[]`, время ≤ NFR-001 (≤ 40 мин)
- [ ] Все unit-тесты проходят на чистой IDE-сессии без базы (заглушки для COM/файлов)
