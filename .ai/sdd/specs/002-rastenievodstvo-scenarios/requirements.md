# Feature: Сценарии растениеводства (спека 002)

> Status: Approved (2026-10-15, «продолжи» = согласие с рекомендованными ответами; Q-001 закрыт безопасным режимом по умолчанию — D-001)
> Source: `.ai/sdd/PLAN.md` (Фаза 3), D-013 спеки 001, `docs/night-report-2026-10-15.md`
> Upstream: `.ai/sdd/specs/001-preprocessor-epf/` — реализован (T1–T9, E2E PASS)

## Overview

Расширение регресс-покрытия конвейера APKScenTest: написать недостающие
шаблоны сценариев Vanessa Automation по документам растениеводства и
довести детализацию данных фикстур до уровня, при котором каждый шаблон
заполняет «свой» документ целиком из фикстуры. Конвейер спеки 001 (скан →
фикстуры → генерация фич → батчи → отчёт) используется как есть.

Кто это для: инженер АПК, проверяющий обновление релиза ERP/АПК на
тестовой базе (см. `.ai/steering/product.md`).

Почему важно: сейчас покрыт один сценарий ввода (01-pl-tractor);
PLAN Фаза 3 требует наборы по группам документов растениеводства.

## Business Context

Конвейер спеки 001 доказал полный цикл E2E
(`tests/run-20261015-003718/`: оба батча ReturnStatus=0). Фикстуры уже
снимают данные с 4 типов документов (тракторный ПЛ, автотранспортный ПЛ,
заправочные ведомости, взвешивания). Не хватает: (а) шаблонов сценариев,
(б) полноты извлекаемых данных (ТЧ, производные поля), (в) представителя
нарядов на сдельную работу (28 найденных документов, представитель не
выбран), (г) определения режима пользователей прогона (реальные авторы
vs временные зонды).

## User Stories

### US-001: Ввод автотранспортного путевого листа

**As a** инженер АПК  
**I want to** чтобы сценарий открывал, заполнял и проводил
АпкПутевойЛистАвтотранспорта по данным фикстуры  
**So that** регресс покрывает вторую по распространённости группу
документов (34 найденных в демо-базе)

**Acceptance Criteria:**
- [ ] Шаблон `02-pl-auto.feature` генерирует фичу без unresolved-плейсхолдеров
- [ ] Фича вводит и проводит документ из фикстуры представителя
- [ ] Батч по шаблону в полном цикле завершается ReturnStatus=0

### US-002: Ввод заправочной ведомости

**As a** инженер АПК  
**I want to** чтобы сценарий вводил и проводил АпкЗаправочныеВедомости  
**So that** покрыта цепочка обеспечения ГСМ

**Acceptance Criteria:**
- [ ] Шаблон `04-fuel-sheet.feature` генерируется корректно и вводит/проводит документ
- [ ] ReturnStatus=0

### US-003: Ввод регистрации взвешивания на току

**As a** инженер АПК  
**I want to** чтобы сценарий вводил и проводил АпкРегистрацияВзвешиванийНаТоку  
**So that** покрыт ток-учёт урожая

**Acceptance Criteria:**
- [ ] Шаблон `05-weighing.feature` генерируется корректно и вводит/проводит документ
- [ ] ReturnStatus=0

### US-004: Отражение АРМами

**As a** инженер АПК  
**I want to** чтобы сценарии отражали документы АРМами
(выработка сотрудников / расход топлива / заправки топлива)  
**So that** проверена связка «документы → АРМ» из плана прогона

**Acceptance Criteria:**
- [ ] Шаблоны `arm-payroll`, `arm-fuel-expense`, `arm-fuel-receipt` реализованы
- [ ] Карта «документ → АРМ» из fixtures.armPlan используются сценарием

### US-005: Детализация данных фикстур

**As a** разработчик конвейера  
**I want to** чтобы фикстуры содержали данные, достаточные для заполнения
документа целиком каждым шаблоном (D-013)  
**So that** шаблоны не зависят от жестко прописанных значений

**Acceptance Criteria:**
- [ ] Критерий достаточности: шаблон заполняет документ целиком из фикстуры,
  проверяется smoke-прогоном (без ручных правок генерированной фичи)
- [ ] ТЧ-данные представлены строками фикстуры (глубина — решением)
- [ ] Производные поля (ТипЗатратСписок, АналитикаРасходовТекущий,
  ХарактеристикаРаботы и т.п.) извлекаются/вычисляются для новых типов

## Functional Requirements

### FR-001: Шаблоны группы путевых листов — Must Have

WHEN план прогона содержит АпкПутевойЛистАвтотранспорта  
THE SYSTEM SHALL сгенерировать фичу из шаблона `02-pl-auto`,
которая открывает, заполняет из фикстуры и проводит документ  
SO THAT покрыта группа автотранспортных ПЛ

### FR-002: Шаблон заправочных ведомостей — Must Have

WHEN план прогона содержит АпкЗаправочныеВедомости  
THE SYSTEM SHALL сгенерировать фичу из шаблона `04-fuel-sheet`,
которая вводит и проводит документ  
SO THAT покрыта цепочка ГСМ

### FR-003: Шаблон взвешиваний — Must Have

WHEN план прогона содержит АпкРегистрацияВзвешиванийНаТоку  
THE SYSTEM SHALL сгенерировать фичу из шаблона `05-weighing`,
которая вводит и проводит документ  
SO THAT покрыт ток-учёт

### FR-004: Шаблоны АРМ — Should Have

WHEN план прогона содержит АРМ из armPlan  
THE SYSTEM SHALL сгенерировать фичи из шаблонов `arm-*`,
которые отражают документы через формы АРМ  
SO THAT покрыта связка «документ → АРМ»

### FR-005: Наряды на сдельную работу — Should Have

WHEN в базе есть проведённые АпкНарядНаСдельнуюРаботу и пользователь
плана соответствует автору  
THE SYSTEM SHALL выбрать представителя наряда и сгенерировать фичу из
шаблона `03-piecework` (ввод/проведение)  
SO THAT покрыты сдельные наряды (28 документов в демо-базе)

### FR-006: Достаточность фикстур — Must Have

WHEN шаблон группы документов извлекает данные представителя  
THE SYSTEM SHALL включить в фикстуру все поля шапки и строки ТЧ
(глубина по решению D-002), необходимые шаблону для заполнения документа
целиком  
SO THAT критерий D-013 выполнен для всех шаблонов спеки

### FR-007: Отчёт полного покрытия — Must Have

WHEN полный цикл завершён  
THE SYSTEM SHALL отразить в summary.json/md все сценарии спеки
(не только один тип)  
SO THAT отчёт отражает реальное покрытие

### FR-008: Объём строк ТЧ фикстуры — Must Have

WHEN документ-представитель содержит ТЧ  
THE SYSTEM SHALL извлекать первые N строк каждой ТЧ (N по решению D-002)  
SO THAT фикстуры предсказуемы и прогоны быстры

## Non-Functional Requirements

### NFR-001: Производительность
- Полный цикл со всеми шаблонами спеки укладывается в разумный бюджет
  времени ночного прогона (ориентир: ≤ 40 минут; текущие батчи — до 2 мин
  на сценарий + накладные расходы на перезапуск клиента тестирования).

### NFR-002: Безопасность (унаследована из спеки 001)
- Подмена паролей — только через штатной механизм спеки 001 с
  гарантированным восстановлением; реальные пользователи — только по
  решению D-001. Конфигурация базы не меняется.

## Out of Scope

- Сценарии животноводства и планирования (релиз 2, см. PLAN Фаза 4).
- Негативные сценарии «нет прав» (по мере необходимости, позднее).
- Веб-клиент (тонкий клиент — основной; веб — Фаза 4).
- Изменение сканера/селектора кроме минимального дополнения для нарядов (FR-005).

## Decisions

### D-001: Пользователи прогона: реальные авторы vs временные зонды

**Decision:** по умолчанию — временные зонды (как в T8 спеки 001).
Переключение на реальных авторов — только по явному подтверждению
пользователя в будущем; механизм полностью реализован в спеке 001,
для включения достаточно снять ограничение манифеста и подменять пароли
реальных авторов. Q-001 закрыт выбором безопасного режима по умолчанию.
**Reason:** безопасность реальных пользователей (запрет «НЕ трогать»
действует с 2026-10-13); зонд-режим не блокирует реализацию спеки 002.
**Source:** Q-001
**Impacts:** NFR-002, FR-001..FR-005 (режим батчей)

### D-002: Глубина ТЧ фикстуры

**Decision:** первые 3 строки каждой ТЧ (N=3).
**Reason:** баланс полноты и скорости прогона (предложение из
`docs/fixture-model.md`).
**Source:** Q-002
**Impacts:** FR-008

### D-003: Негативные сценарии

**Decision:** не включаются в спеку 002 (PLAN: «по мере необходимости»).  
**Reason:** приоритет — покрыть позитивные сценарии всех групп
документов; негативные не блокируют бизнес-ценность.  
**Impacts:** Out of Scope

## Questions

### Q-001: Под чьими правами гонять сценарии спеки 002?

**Status:** answered — выбран безопасный режим по умолчанию (зонды),
см. D-001; расширение на реальных авторов — отдельным решением пользователя.  
**Why it matters:** определяет, задействован ли главный механизм
продукта (подмена паролей реальных авторов) или прогон остаётся на
временных пользователях; меняет объём работ и риски.  
**Recommended:** Option A — штатная цель продукта.

| Option | Answer | Choose this if | Impact |
|--------|--------|----------------|--------|
| A | Реальные авторы (подмена пароля → прогон → восстановление) | хотим проверить движение документов под реальными правами (роли, RLS) | пароли реальных пользователей подменяются и восстанавливаются; гонки с живыми пользователями недопустимы |
| B | Временные зонды (как в T8) | максимальная безопасность | механизмы RLS/прав не проверяются на 100% |
| Custom | … | нужна третья схема | обновить требования |

### Q-002: Сколько строк ТЧ помещать в фикстуру?

**Status:** answered — N=3 (см. D-002).  
**Why it matters:** влияет на длительность прогона и достаточность
данных шаблонов.  
**Recommended:** Option B — N=3 (из предложения fixture-model).

| Option | Answer | Choose this if | Impact |
|--------|--------|----------------|--------|
| A | Все строки | документы малы, полнота важнее | фикстуры тяжелее, прогон дольше |
| B | Первые 3 строки каждой ТЧ | баланс полноты и скорости | FR-008: N=3 |
| C | Первая строка каждой ТЧ | минимальный smoke | часть проверок уйдёт |
| Custom | … | другое | обновить FR-008 |

### Q-003: Включать ли наряды на сдельную работу (FR-005)?

**Status:** answered — включаем как Should Have (см. FR-005).  
**Why it matters:** 28 найденных документов, но авторы не попали в
сопоставление пользователей (у представителя наряда нет пользователя ИБ в
плане?) — включение требует разобраться в сопоставлении; это план Фазы 3
PLAN, но не в текущем plan'е прогона спеки 001.  
**Recommended:** Option A — включить как Should Have.

| Option | Answer | Choose this if | Impact |
|--------|--------|----------------|--------|
| A | Включить (Should Have) | полный план Фазы 3 PLAN | FR-005 остаётся, объём +1 шаблон |
| B | Отложить на спеку 003 | не хочется разбирать сопоставление сейчас | FR-005 удаляется, фиксируется в Decisions |
| Custom | … | другое | обновить FR-005 |

## Glossary

- **Шаблон** — `tests/templates/NN-*.feature` с плейсхолдерами; генератор
  препроцессинга подставляет данные фикстур (TD-008 спеки 001).
- **Представитель** — отобранный сканером документ, данные которого
  попадают в фикстуру (D-014 спеки 001).
- **Зонд** — временный пользователь ИБ АпкСценТест_Зонд*, создаваемый
  препроцессингом на время прогона.
