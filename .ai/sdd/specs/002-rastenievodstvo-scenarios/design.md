> Requirements: @requirements.md
> Status: Approved (2026-10-15, «продолжи» — согласие с планом; отклонения — по запросу)

## 1. Summary

Дописываем 6+ шаблонов .feature (3 док. типа, наряды, 3 АРМ), расширяем
экстрактор фикстур (полный состав ТЧ, N=3 строки — D-002) и расширям
манифест батчей. Конвейер спеки 001 не меняем: та же генерация из
шаблонов (TD-008), те же батчи (порт per user + сироты), тот же отчёт.
Новые шаблоны пишем по playbook'у 01-pl-tractor (probe-first, грабли 8.5.4
зафиксированы в `docs/next-session-prompt.md`).

## 3. Technical Approach

### 3.0. Порядок реализации (probe-first, как в T8 спеки 001)

Каждый шаблон = «probe-фича → правки шаблона → повтор», и только когда
шаблон стабильно проходит под админом (без подмены пароля, без записи
данных — если документ создаётся в probe, он удаляется), включаем его в
манифест полного цикла. Полный цикл — только после стабилизации всех
шаблонов.

### 3.1. 02-pl-auto (FR-001)

Форма аналогична тракторному ПЛ (e1cib/data/Документ.АпкПутевойЛистАвтотранспорта),
отличия: Водитель вместо Механизатора, Автомобиль вместо Техники,
СпидометрВыезд/Возвращение (числа), ТЧ ЗаданиеВодителю (ПунтОтправки/
Назначения — dropdown АпкТочкиМаршрута). ТЧ ВыполненныеРаботы — БЕЗ
Гектаров, но с Километров/Тонн/Часов; ТипЗатрат присутствует. Проверить
по Form.xml: есть ли колонка АналитикаРасходов — если да, повторить
UIA-рецепт (создание объекта текущего периода уже идемпотентно покрыто
`scripts/t8_create_objekt.py`); если нет — убрать соответствующие шаги.

### 3.2. 04-fuel-sheet (FR-002)

АпкЗаправочныеВедомости: шапка (Организация/Подразделение/Склад/
ТранспортноеСредство/Сотрудник/ВыдачаСТопливозаправщика/НаемноеТС) +
ТЧ ГСМ (МаркаТоплива dropdown, Количество число). Существенно проще
тракторного ПЛ — не должно быть новых механизмов.

### 3.3. 05-weighing (FR-003)

АпкРегистрацияВзвешиванийНаТоку: шапка (ВидВзвешивания dropdown, Откуда/
Куда — ref-dropdown; Номенклатура/Характеристика) + ТЧ Талоны (НомерТалона,
Комбайн, Механизатор, Масса). Серии — по данным представителя (0 строк).
«Откуда» у представителя = объект затрат (текущий период: создан в T8) —
если поле ref-dropdown с формой выбора не по UIA-клику (проверить:
АпкФормаВыбора открывается ТОЛЬКО у АналитикиРасходов тракторного ПЛ
через НачалоВыбора; у взвешивания «Откуда» — стандартный выпадающий
список, ввод «по строке»), особых шагов не требуется.

### 3.4. arm-* (FR-004)

3.4.1. ИССЛЕДОВАНИЕ (критично — новые формы, неизвестная механика):
АпкАРМПоОтражениюВыработкиСотрудников / АпкАРМПоОтражениюРасходаТоплива /
АпкАРМПоОтражениюЗаправокТоплива (обработки АРМ). Нужно по исходникам
APKModSrc + скану демо-базы выяснить: как АРМ открывается (e1cib/app/
e1cib/data?), как находит документы к отражению, какие кнопки нажимаются,
что является успешным результатом (проводка? запись регистров?).
БЕЗ этого шага АРМ-шаблоны не пишем — если механика окажется сложной
(например, АРМ отражает только проведённые документы за период), фиксируем
в PROGRESS и упрощаем скоуп (Should Have).
3.4.2. После разведки — probe-фича под админом, без записи, или с
записью+откатом; если отражение меняет данные (регистры) — отражаемые
документы фикстур НЕ отражаем, а создаём копию (или используем механизмы
отмены, если есть).

### 3.5. Достаточность фикстур (FR-006/008, D-013 спеки 001)

Экстрактор (`ObjectModule.bsl`) уже собирает header + tabular по типам.
Расширяем: (а) состав колонок ТЧ — до полного покрытия всех колонок,
которые нужны шаблону (как сделано для ВыполненныеРаботы тракториста в
t8-finish-6: columns задаются в `tests/coverage-map.json` fieldList.tabular);
(б) N=3 строки (D-002) — сейчас 0–2; (в) производные поля
(ТипЗатратСписок, АналитикаРасходовТекущий) — для каждого нового типа
документа с ТипЗатрат.

### 3.6. Наряды (FR-005)

Диагноз (по данным спеки 001): 28 нарядов, представитель не выбран —
причина: у автора представителя нет пользователя ИБ в плане прогона, или
селектор пропустил тип. Разобраться: COM-диагностика авторов нарядов,
проверить `Пользователи.ИдентификаторПользователяИБ` для авторов. Если
маппинг восстановим — представитель + шаблон 03-piecework (шапка
Исполнитель, ТЧ Задание: ВидРаботы, Часы/Тонны/Гектары, ТипЗатрат — шаг
«с выбором»; ТипЗатрат + Аналитика — как в тракторном ПЛ, проверив
наличие колонки АналитикаРасходов у наряда по Form.xml). Если маппинг
невосстановим (авторы — вне плана прогона) — документируем и берём наряд
с автором = ОрловАВ/СоколовМИ (если есть такой наряд) или иным уже
сопоставленным автором.

### 3.7. Отчёт (FR-007)

summary.json/md уже агрегирует все батчи (T7/T8 спеки 001) — код не
меняем, в AC включаем проверку, что все сценарии спеки видны в отчёте.

## 5. Data Model / State

fixtures.json — расширение структуры `documents[].data.tabular[<ТЧ>][]`
(состав колонок + 3 строки). Ключи производных полей — как в спеке 001:
`ТипЗатратСписок` (valueMaps), `АналитикаРасходовТекущий` (объект затрат
текущего периода). Структура `{uuid, presentation}` для ref-полей.

## 6. API / Integration Contract

Меняется публичный контракт — структура МАНИФЕСТА фич (features-manifest.json):
шаблон `02-pl-auto` привязан к `АпкПутевойЛистАвтотранспорта`, `04-fuel-sheet`
к `АпкЗаправочныеВедомости`, `05-weighing` к `АпкРегистрацияВзвешиванийНаТоку`,
`03-piecework` к `АпкНарядНаСдельнуюРаботу`, arm-* — по плану armPlan.
Формула манифеста в `runner_module_src.bsl` (если правка нужна — пересборка
через `scripts/build_t6.py`).

## 7. Security / Permissions / Privacy

- Режим прогона (D-001): временные зоны АпкСценТест_Зонд*; манифест
  ограничен зонадами. Реальные авторы — НЕ трогаем до явного разрешения
  пользователя (риск: их сценарии — pending user confirmation).
- Подмена паролей — только штатной логикой спеки 001 с гарантированным
  восстановлением; пароли восстановления (хэш/ЗОД) фиксируются в
  summary.json каждой смены.
- Если arm-* отражает документы (меняет данные), в probe под админом:
  запись разрешена только для документов, созданных самим probe, с их
  удалением/отменой после; отражение документов фикстур — только если
  отражение идемпотентно или документ уже был отражён. Предпочтительно:
  в probe использовать созданную копию документа, не фикстуру.
- Конфигурация базы НЕ меняется (как и в спеке 001).

## 9. Edge Cases

| Case | Expected Behavior |
|------|-------------------|
| Представитель наряда: автор не сопоставлен с ИБ-пользователем | FR-005: искать наряд с сопоставленным автором; если нет — документируем и откладываем шаблон, пометив FR-005 отклонённым с пояснением |
| ТЧ ЗаданиеВодителю у представителя пуста (0 строк) | шаблон 02-pl-auto пропускает блок; в отчёте — проверка блоков по данным фикстуры (см. грабли 01-pl-tractor про обязательные ТЧ) |
| Колонка АналитикаРасходов отсутствует у автотранспортного ПЛ / наряда | шаблон без UIA-блока аналитики |
| АРМы: отражение меняет регистры | создаём копию документа для отражения в probe; не отражаем реальные документы фиксtures силами сценария |

## 11. Observability / Operations

- Продолжаем вести `tmp/t*/PROGRESS.md` + heartbeat (дисциплина спеки 001).
- Бюджет времени: батч 1–2 мин; клиент стартует ~30–60 с на сценарий

  25–35 мин — укладывается в NFR-001, контролируется в AC.

## 13. Technical Decisions

### TD-001: Новые шаблоны — одинаковые рецепты шагов, никаких новых механизмов VA

- **Decision:** все новые шаблоны используют ТОЛЬКО механизмы,
  доказанные в T8 спеки 001 (dropdown «по строке», шаг «с выбором» с
  деривацией, UIA-двойной клик для Аналитики, закладки «К», текущая дата).
- **Why:** все новые механизмы VA на 8.5.4 — риск провалов, как
  ListChoiceMode у ТипЗатрат.
- **Trade-off:** возможен отказ от какого-то действия, если механизма
  нет (пример — Моточасы) — вместо этого пропускаем блок и фиксируем.
- **Alternatives considered:** писать новые механизмы через библиотеки
  шагов — отклонено (противоречит D2 решения плана: «без библиотеки
  кастомных шагов»).

### TD-002: Экстрактор — расширение на месте (ObjectModule.bsl), карточка колонок в coverage-map.json

- **Decision:** расширяем экстрактор фикстур как в t8-finish-6: полный
  список ТЧ-колонок в `fieldList.tabular` + N=3 (D-002) + производные
  поля по тем же valueMaps.
- **Why:** минимальное изменение кода; состав полей — внешние данные
  (TD-001 спеки 001), не в метаданных.
- **Trade-off:** расширение одного метода — снижение читаемости
  (компенсируется комментариями).
- **Alternatives considered:** собственный класс извлечения — отклонено
  (масштаб проекта не оправдывает).

### TD-003: arm-* — разведка форм АРМ ДО написания шаблонов

- **Decision:** перед arm-* обязательно исследовать АРМы по исходникам
  APKModSrc + пробному open под админом; по результатам — решение,
  какие шаги шаблона вообще возможны, или фиксация отклонения FR-004
  со сводкой в отчёте.
- **Why:** АРМ — внешние обработки со своей формой и неизвестной
  механикой отражения; шаблон «наобум» провалит probe-first.
- **Trade-off:** дополнительная фаза разведки (больше работы).
- **Alternatives considered:** просто попробовать — отклонено
  (нарушает probe-first; 2-attempt-правило).

### TD-004: Наряды — сопоставление авторов не обходим, а исследуем и подключаем

- **Decision:** первым шагом FR-005 — COM-диагностика авторов 28
  нарядов и их связи с пользователями ИБ (только чтение).
- **Why:** документ в PLAN Фазы 3; вероятно, у нарядов другой автор,
  который не попал в план пользователей (одна из двух учётных записей
  не автор нарядов) — надо проверить, а не предполагать.
- **Trade-off:** +1 задача в спеке (Should Have).

## 15. Verification Strategy

- Каждый шаблон: probe-прогон (ReturnStatus=0) до включения в манифест.
- Полный цикл: `python scripts/t8_gate.py` (или новый gate-скрипт спеки 002) —
  все батчи rs=0, summary passed, пароли/ЗОД восстановлены, сирот нет.
- Гейты bsl-ls + v8std после правок BSL (EXT-модуль экстрактора).
- Отчёт ночи + handoff (документируется в PROGRESS.md).

## 16. Implementation FAQ

**Q:** Использовать существующий скрипт `t8_gate.py` или новый?
**A:** Расширяем существующий (его структура stages + порты + сироты
достаточны; новые шаблоны попадают в манифест автоматически).

**Q:** Что если probe какого-то шаблона регулярно падает?
**A:** 2-attempt-правило: две попытки с одним механизмом = стоп и
документируем; отключаем шаблон от манифеста, в отчёте — пометка
«не стабилен, отключён».

**Q:** Нужны ли новые VAParams-флаги?
**A:** Нет: схема фиксируется на трёх флагах T8 (VanessaExt=Истина,
UIAutomation=Истина, ЭмулироватьДвиженияМышкиVanessaExt=Ложь).
