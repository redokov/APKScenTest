# APKScenTest — сценарные регрессионные тесты блока «Растениеводство» АПК

Набор сценарных тестов Vanessa Automation для проверки работоспособности
функционала блоков «Растениеводство» и «Животноводство»
(СВН + молочный КРС) конфигурации **1С:ERP + модуль «Агропромышленный
комплекс» 2.5** (например, после обновления релиза) на тестовой базе.

## Концепция

Наглядно принцип работы тестера (4 схемы): [`docs/how-tester-works.md`](docs/how-tester-works.md)
— полный цикл, механизм подмены паролей, группы проверок и вердикт,
регрессия после обновления. Там же есть словарь терминов.

1. **Обработка препроцессинга** (запуск всегда от администратора) сканирует
   введённые документы подсистемы АПК: путевые листы, сдельные наряды,
   заправочные ведомости, регистрации взвешиваний, а также животноводство:
   опоросы/отёлы, журналы надоя, переводы/падёж/поступления животных,
   ТТН и внутренний расход молока, учётные листы СВН/КРС.
2. Из найденных документов извлекаются элементы заполнения сценариев:
   организация, подразделение, номенклатура, ответственные, техника,
   **пользователи-авторы** (тесты выполняются под их правами).
3. Препроцессинг заполняет сценарные тесты полученными данными и запускает
   Vanessa Automation.
4. Пароли пользователей не знаем и не храним: их хэш
   (`СохраняемоеЗначениеПароля`, платформа 8.5) сохраняется, устанавливается
   временный пароль, после прогона хэш восстанавливается.
5. Итог — отчёт (целевой формат — Allure).

## Целевая архитектура (коррекция цели, 28.10.2026)

**Продукт = установочный комплект на языке 1С:Предприятия.** Рабочий
прогон целиком в сеансе тестируемой базы: препроцессор (EPF, от
администратора) готовит данные → раннер (EPF, от администратора) гонит
тесты → **итоговый отчёт показывается в этой же сессии 1С**. В рабочем
процессе **нет python, COM и LLM**. Сервер, лицензии, запасная копия и
возврат базы — обеспечивает инженер (инструкция в комплекте), комплект
их не исследует. Состав комплекта — только: препроцессор EPF, раннер EPF,
Vanessa Automation single EPF, сценарии `.feature`, инструкция.

> История: в фазах 3–4 цель мигрировала в python-стенд (`scripts/regress_run.py`
> + служебная обвязка COM/rac) — полезный инструмент валидации для
> разработчика, но не продукт. Коррекция зафиксирована:
> `.ai/steering/product.md` → «Целевая архитектура», план —
> `.ai/sdd/PLAN.md` → Фаза 6, исполнение — спека
> `.ai/sdd/specs/005-pure-1c-kit/`.

## Состав комплекта dist/

Установочный комплект (пересобран `build_dist.py` 03.11.2026, принят
сквозными прогонами s012/s013):

| Файл/каталог | Назначение |
|---|---|
| `dist/АпкПодготовкаСценарныхТестов.epf` | Препроцессор: чтение документов АПК, генерация `.feature` по данным базы (исправления — из `scenario-patches.json`, без python) |
| `dist/АпкРаннер.epf` | Раннер: группы проверок по пользователям-авторам, подмена/восстановление хэшей паролей, сверка с эталоном, итоговая форма отчёта в сеансе 1С |
| `dist/vanessa-automation-single.epf` | Vanessa Automation single (движок прогона сценариев) |
| `dist/scenarios/` | 30 файлов: 27 `.feature` (5 типов документов растениеводства + 6 СВН + 8 КРС + 5 «отражений» АРМ + смоук + 2 отказных) + `baseline.json`, `baseline-real.json` (46 записей эталона), `scenario-patches.json` |
| `dist/ИНСТРУКЦИЯ.md` | Инструкция инженера: что обеспечить до запуска (сервер, лицензии, сеансы, запасная копия/возврат базы) |

Рабочий прогон комплекта целиком в сеансе 1С: препроцессор → раннер → отчёт
в той же сессии, без python/COM/LLM. Python-хелперы `scripts/` — только
служебная обвязка для разработчиков (восстановление базы, отказной
пользователь, запуск цепочки VA), в комплект не входят.
